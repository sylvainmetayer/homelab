# CI (GitHub Actions) and Renovate

Moved from `AGENTS.md` (agent-facing notes, kept in English); the index there links here.

- `.github/workflows/lint.yaml` — `ansible-lint`, `.github/scripts/check_sops_shadowing.py` (no key of `secrets/ansible.sops.yaml` or `fake_secrets.yml` may bear the name of a play, `roles:` entry, block, task or `import_role` `vars:`, nor of a role's `vars/`), `.github/scripts/check_immich_versions.py` (`immich-server` and `immich-machine-learning` at one version in every compose that cites them: Renovate's group is not atomic, `compose/immich/README.md`), the unit tests of the CI scripts (`.github/scripts/test_*.py`, `python -I -m unittest discover -s .github/scripts -p 'test_*.py'`: `resolve_docker_tags.py` decides what a merge deploys, `select_tests.py` what a PR tests), `tofu fmt -check` and `tofu validate` (pangolin, proxmox, pangolin_config, dns, github, ref, s3_state, keepass_backup, site, 1y, keycloak_demo_planning_kc) on every PR.
- **SOPS files in CI** (ADR 0018): they live in the private `homelab-secrets` repository, mounted as the `secrets/` submodule. The jobs that read them (Lint's `Ansible lint`, `deploy-docker-app`, `secrets-rotation`) call `.github/actions/secrets-checkout` after the main checkout: it reads the commit the submodule pins (`git ls-tree HEAD secrets`) and checks it out into `secrets/` with the read-only deploy key `HOMELAB_SECRETS_SSH_KEY`, a **repository** secret (`tofu/github/repository_homelab_secrets.tf`; an environment is main-only and Lint runs on PRs), credentials not persisted. A fork PR gets no secret, so its `Ansible lint` fails. Tests (Molecule on `fake_secrets.yml`, `tofu test` on `override_data`) never clone it; `select_tests.py` classifies a submodule bump (`secrets`) as test-free.
- `.github/workflows/lint.yaml`, job `CI lint` — zizmor (actions pinned by SHA, template injection, persisted checkout credentials), actionlint (`.github/actionlint.yaml` declares the `ubuntu-26.04` label) and hadolint on the Molecule Dockerfile (`.hadolint.yaml`), all as pinned binaries checked by sha256. Locally: `mise run lint-ci`. Every `actions/checkout` sets `persist-credentials: false`; a matrix value reaches a `run:` through `env:`, never as `${{ … }}` inside the script. Secrets: `mise run secrets-scan` (gitleaks over the whole history, `.gitleaks.toml` lists each known false positive with its reason) and `mise run install-hooks` (gitleaks pre-commit hook on staged changes).
- `.github/workflows/deploy-docker-app.yaml` — on a push to `main` touching `ansible/roles/**`, a host playbook, `ansible/host_vars/<host>/` of a CI-deployed host (docker, pi, pangolin, flip), `ansible/group_vars/all/**`, `ansible/tasks/**` or `ansible/requirements.yml` (or by hand, `workflow_dispatch` with forced `tags`), opens the OLM tunnel and runs the playbooks with the tags `resolve_docker_tags.py` derives from the changed files. A role's own `README.md` is skipped: documentation, never read by Ansible, it deploys nothing. A changed playbook is compared as YAML with the diff base (`--base`): the `roles:` entries added or changed (their `vars:`, e.g. one `flip_planning` instance) deploy their own tags (not one other entries share, like `monitoring`, when they have another), a comment or a removed entry deploys nothing, and anything else (pre_tasks, tasks, play keys, an untagged entry, no readable base) runs the whole playbook (`--tags all`, which still skips `never`). A `host_vars/<host>/` change runs that host's whole playbook (which role reads which variable is not derived; an idempotent run restarts nothing). A change to a file every playbook reads, `ansible/group_vars/all/**`, `ansible/tasks/**` (the shared pre_tasks, `pangolin_config_outputs.yml`) or `ansible/requirements.yml` (galaxy roles and collections), runs all four playbooks whole: heavy, but no change is lost. Left out on purpose: `ansible/secrets.sops.yaml` (a rotation is applied by hand, in the runbook's order), and the files that change no host: `ansible.cfg`, `known_hosts`, `inventory/` (the CI writes its own `ci-inventory.ini`), `ansible/mise.toml`, `molecule/`, `uv.lock`. The YAML is compared net from the base: a revert of a half-applied playbook change deploys nothing, re-run it by hand. Runs are serialized (`concurrency: deploy-docker-app`, OLM refuses a second connection), and GitHub keeps one **pending** run per group: a third push cancels the pending one. So the changed files are diffed from the head of the **last successful push run** (read through the API, `actions: read`), not from the push's own `before`: the next run catches up a cancelled or failed one, a run failing halfway is retried whole (idempotent), dispatch runs never count as a base, a re-run of a commit older than that base deploys nothing (it would roll back), and an API error fails the run rather than deploy only the push. The files are those of every commit of the range plus the net diff (a revert of a half-applied commit nets to nothing), and each host's `Deploy` step runs even when an earlier one failed (`!cancelled()`), or a host that stays down would block the others in every run.
- `.github/workflows/test.yaml` — discovers `ansible/molecule/*/molecule.yml` and `tofu/*/tests/` and runs one matrix job per Molecule scenario and per tested Tofu module (see `docs/conventions/tests.md`). On a PR, only the suites the changed files reach (`.github/scripts/select_tests.py`, read from the tree: a scenario's roles followed through meta dependencies and `include_role`/`import_role`, the paths its files reach — host_vars, another scenario, a playbook —, a module's `file()`/`fileset()` reads; `_shared`, `group_vars`, `requirements.yml`, `uv.lock` rerun every scenario, `mise.toml` every module, `test.yaml` or the script everything, an unclassified file everything, docs nothing); a `full-tests` label, `workflow_dispatch` and the weekly run (Monday 03:30 UTC, `schedule`; no `push` trigger) run the full matrix. A dependency the script cannot read (a path built at runtime) is missed on the PR and caught by the weekly run: teach it to `select_tests.py`. The `Molecule image` job builds `homelab-molecule:debian13` once into the GitHub Actions cache (buildx, `type=gha`, scope = Dockerfile hash), each Molecule job loads it from there. `Tests` stays the one required check, green when the matrices are empty. A new push to a PR cancels its running Tests and Lint runs (`concurrency`).

- `.github/workflows/codeql.yaml` — CodeQL in advanced setup (languages `actions` and `python`, build mode none, default query suite): weekly (Monday 04:30 UTC), by hand, and on the PRs and pushes to `main` touching `.github/scripts/**` or the workflow itself, not on every push/PR. GitHub's CodeQL *default setup* must stay disabled (Settings → Code security): it refuses the results of an advanced workflow while it is on.

- Renovate (`renovate.json`) automerges, through GitHub auto-merge once the `main` ruleset's four checks pass (so the merge deploys): our own images (`planning-equipes` patch/minor and the demo's main digest, `promptoramix`), and the Monday PR « weekly stateless automerged updates » — digest and patch updates of an **allowlist** of stateless images (no DB of their own, no data migration: gotenberg, tika, stirling-pdf, homepage, karakeep-chrome, rclone, and debian, the Molecule image's base; never in `ansible/roles/flip_planning/**`, whose restart takes the production planning and its Postgres along) and patch updates of GitHub Actions `uses:` (depType `action`; never their digest updates: a new digest under an unchanged tag is a moved tag, and an action runs next to the production secrets). Molecule pulls no image: a merged image that crashes leaves the deploy green and only its Uptime Kuma monitor tells; revert **and** drop it from the allowlist, or Renovate re-merges it the next Monday. Everything else (DB images, apps migrating their data or with a DB of their own, Traefik, the socket proxy, vmauth, the role groups, mise tools, minors and majors) stays manual. A paused app gets no PR at all (« Paused apps » rules, `enabled: false` on `ansible/roles/paperless_ngx/**` and on its image in `path_bypass_images.json`, or the json alone would be bumped and fail `path_bypasses_follow_their_image`; resuming removes both). Cadence (2026-10-29, after 152 Renovate PRs merged in 30 days): every third-party update waits `minimumReleaseAge: 3 days` (top level; images, GitHub Actions, mise tools, binaries; our own images and the Karakeep Button git ref, which has no release timestamp, reset it to `null`), so with the Monday window a release waits 3 to 10 days; digest/patch updates go to the Monday PR « weekly digest and patch updates » (manual) unless the stateless allowlist takes them, minor updates open on Monday only, one PR per package (manual, never automerged, not grouped: each app's data migration is read and deployed on its own), the `groupName` rules (beszel, vector, blocky, pangolin-role-dependencies, socket-proxy, borgmatic, immich-role-dependencies) keeping their own PR on that same schedule; every major update gets no branch nor PR until its box is ticked in the Dependency Dashboard (issue #5, `dependencyDashboardApproval`); our own images (`planning-equipes`, `promptoramix`) are exempt from the delay, the window and the major approval (a planning-equipes major still opens its PR at once, merged by hand). `rebaseWhen: conflicted` is global: the `main` ruleset does not require an up-to-date branch (`strict_required_status_checks_policy = false`), so a PR is rebased only on a conflict (the default `auto` already did so for the manual PRs; the top-level setting extends it to every automerged one, our own images' included). The fast path for an image security fix is not Renovate (GitHub vulnerability alerts, which Renovate would follow without delay nor schedule, are off on this repo and cover no image anyway): the Monday `trivy.yaml` ntfy alert lists each fixable CRITICAL with its fixed version, bumped by hand or forced from the Dependency Dashboard. Renovate automerges a branch only if every update in it does: a group mixing both never automerges. Never add an image of `path_bypass_images.json` to the allowlist: its bump needs a human re-read of the public paths before the merge (the last `packageRules` entry sets `automerge: false` on that file as a guard, plus the PR note listing what to re-read).

- `.github/workflows/restore-test.yaml` — on the 1st and the 15th, restores on a runner the latest archive of every borg repository of `.github/restore-test/apps.json` (`host`/`repo`/`role`, kept equal to the backup monitors by `pangolin_config`'s tests): fails on an archive older than 28 h (one missed night), extracts a sample, replays SQL dumps in a throwaway container of the role's DB image, runs SQLite `integrity_check`; a last job pushes the overall result to the single `Restore test` Uptime Kuma monitor (20 days). Secrets live in the `restore-test` environment (main only, not `production`: no age key): the **read-only** `restore-test` Storage Box subaccount (home `backup/`, `tofu/pangolin/storage_box.tf`, key uploaded by `ansible/backup.yaml`, hence `borg --bypass-lock`) and `backup_passphrase`. See `.github/restore-test/README.md`.

- `.github/workflows/storage-box-quota.yaml` — every Monday (06:00 UTC), `.github/scripts/storage_box_quota.py` reads the backup Storage Box's usage (`stats.size`, data and snapshots) against its plan size (`storage_box_type.size`) through the Hetzner API, and fails at 80 % or more; it pushes up, or down with the percentage (also on an API error), to the `Storage Box` Uptime Kuma monitor (8 days, `tofu/pangolin_config/storage_box_quota_monitor.tf`). Own environment `storage-box-quota` (main only, `tofu/github/environments.tf`): a **read-only** Hetzner project token (SOPS `hcloud_readonly_token` in `secrets/ansible.sops.yaml`, made by hand in the Console), never tofu/pangolin's read-write `HCLOUD_TOKEN`, and the monitor's push URL.

- `.github/workflows/renovate-digest.yaml` — every Monday (13:00 UTC, after Renovate's morning run and the automerges it unlocks), `.github/scripts/renovate_digest.py` lists over 7 days the Renovate PRs merged (automerged, i.e. merged by Renovate itself, then by hand; repeated bumps of one package grouped as `xN`), the open Renovate PRs with their age (oldest first, auto-merge pending flagged) and the failed `deploy-docker-app.yaml` runs (a failure followed by a successful push run is marked caught up and no longer raises the priority), through the job's read-only `GITHUB_TOKEN` (GraphQL search + REST runs; `contents`, `pull-requests`, `actions: read`), and publishes it to ntfy's `/` on topic `github` with the `ntfy-github` environment's `NTFY_GITHUB_TOKEN` (`ntfy_github_token`: publisher `github` of the ntfy role, its own token, not the hosts' `scripts`). Full text in the run summary; an API error still publishes a message and fails the run.

- `.github/workflows/secrets-rotation.yaml` — every Monday (06:30 UTC), `.github/scripts/check_secret_rotation.py --due` reads `secrets/secrets-rotation.yaml` (submodule of the private `homelab-secrets` repository, ADR 0018: one entry per key of both SOPS files, with its `kind`, `last_rotated` date and `how` link into `docs/runbooks/rotation-des-secrets.md`) and fails when a secret is due within 30 days or overdue: `provider` tokens yearly, `application` secrets every two years, `database` and `encryption` on incident only, `identifier` never. It pushes up, or down with the key names, to the `Rotation des secrets` Uptime Kuma monitor (8 days, `tofu/pangolin_config/secrets_rotation_monitor.tf`). Own environment `secrets-rotation` (main only, `tofu/github/environments.tf`): the push URL only, no age key (SOPS key names are plaintext). Without `--due`, the same script runs in the Lint workflow and fails on a SOPS key missing from the inventory, an entry whose key is gone, or an invalid entry. Both modes also read `dernier_test` in the front matter of `docs/runbooks/test-cle-secours.md` (the quarterly decryption test of the offline `secours` age key, run by hand with `mise run test-cle-secours <keyfile>` — `.github/scripts/secours_key_check.py`, which sets the date when it passes; Lint fails on a missing, invalid or future date, `--due` pushes down past 100 days). The Lint workflow also runs `.github/scripts/check_age_recipients.py`: each `*.sops.yaml` must be encrypted for exactly the recipients of the first `.sops.yaml` rule matching it (read from its plaintext `sops:` metadata, nothing decrypted), and every rule must list `secours` and only post-quantum (`age1pq1…`) recipients. sops adds `SOPS_AGE_KEY_FILE` to the other keys it finds (`~/.config/sops/age/keys.txt`…), so testing one key means an isolated `env -i HOME=<empty dir>` run, as the runbook does.

- `.github/workflows/trivy.yaml` — every Monday (05:00 UTC), Trivy scans every pinned image (`.github/scripts/trivy_images.py`, HIGH/CRITICAL with a fix only, `--ignore-unfixed`; one JSON report per image, converted to SARIF for code scanning) and the configuration. Its `notify` job (main only, environment `ntfy-github`, shared with the Renovate digest: `tofu/github/environments.tf`, the `github` producer's ntfy token `ntfy_github_token`, like every CI publisher) publishes the fixable CRITICAL ones, per image with the fixed version, to the ntfy topic `github` (`.github/scripts/trivy_critical.py`); none, no message.

- `.github/workflows/ping.yaml` — manual (`workflow_dispatch`) connectivity test that starts an `fosrl/olm` (Pangolin's Outline-like mesh client) container on the runner, points the runner's system DNS at the OLM DNS proxy, and validates both public internet access and reachability of a private Pangolin resource (`docker-apps.internal:22`). Useful as a template if debugging OLM/Pangolin tunnel DNS issues — the key gotcha documented inline: `OVERRIDE_DNS=true` only rewrites `/etc/resolv.conf` *inside* the OLM container (different mount namespace), so the runner's own resolver must be repointed manually at `100.96.128.1`.
