# Ansible: playbooks, inventory, config layering

Moved from `AGENTS.md` (agent-facing notes, kept in English); the index there links here.

## Running a specific Ansible playbook

There is no `site.yml`: from `ansible/`, target the playbook for the host group you're changing:

```bash
ansible-playbook 00-setup.yaml   # base host setup (user, packages, starship)
ansible-playbook docker.yml      # Proxmox docker host: all the app roles
ansible-playbook flip.yml        # Hetzner flip server: Flip Planning (prod, demo, Keycloak demo), Promptoramix
ansible-playbook pangolin.yaml   # Pangolin Hetzner VM
ansible-playbook pi.yml          # Raspberry Pi (Immich, Blocky)
ansible-playbook lxc.yml         # Proxmox Newt LXC (site proxmox-lxc, Blocky); by hand only
ansible-playbook nas.yml         # Ugreen NAS (Jellyfin, NAS Traefik, kDrive copy); by hand only
ansible-playbook pve.yml         # Proxmox VE host (Beszel agent, vzdump restore test, update notices); by hand only
ansible-playbook backup.yaml     # authorizes each host's borgmatic key on its Storage Box subaccount
ansible-playbook test.yaml
```

No `-i`: `ansible.cfg` sets `inventory = ./inventory`, i.e. `proxmox.py`, `hetzner.py` and `hosts` together. `-i inventory/hosts` alone would only know the static hosts (Pi, LXC, NAS, Proxmox host).

Add `--check` for a dry run, `--tags <tag>` to scope to one role/app (e.g. `--tags betisier`), and `-v`/`-vv`/`-vvv` for verbosity. `ansible.cfg` sets `stdout_callback = debug` and logs every run to `ansible/run.log`; fact cache lives in `ansible/facts/`. It also turns SSH pipelining on (`pipelining = True`, one SSH round trip per task, mirrored in Molecule by `ANSIBLE_PIPELINING`), which needs `requiretty` absent from every host's sudoers: check it on any new host (`sudo grep -r requiretty /etc/sudoers /etc/sudoers.d`).

**Inventory** is dynamic: `ansible/inventory/proxmox.py` and `ansible/inventory/hetzner.py` read the corresponding `tofu state -json` output (via `tofu show -json` run against `../tofu/proxmox` or `../tofu/pangolin`) to build host lists — so `tofu apply` must be current before an inventory-dependent Ansible run picks up new hosts. `ansible/inventory/hosts` holds the static hosts: the Raspberry Pi, the Newt LXC (`newt_lxc` group, host `newt-lxc`; `proxmox.py` only reads VMs), the NAS (`ugreen` group, host `nas`) and the Proxmox host (`proxmox_ve` group, host `pve`). A Hetzner server with no public IPv4 (flip) is emitted by `hetzner.py` with its private IP and a `-o ProxyCommand="ssh … -W %h:%p sylvain@<pangolin public IP>"` that checks the bastion against `ansible/known_hosts` (Pangolin's sshd allows it via `security_ssh_allow_tcp_forwarding: local` in `host_vars/pangolin`); CI does the same (private IP + `ProxyJump=pangolin.sylvain.cloud`, bastion key in the runner's `~/.ssh/config`). Never point Ansible at `flip.internal`: that Pangolin private resource is served by flip's own Newt, so a play restarting newt or docker there cuts its own connection; it is only for manual access through a Pangolin client.

## Host groups / playbook mapping

| Playbook | Host group | Purpose |
|---|---|---|
| `00-setup.yaml` | `all,!backups,!nas,!pve` | base setup: apt packages, timezone, `sylvain` user + SSH keys from `keys/*.pub`, starship prompt, `ssh_login_notify` (Uptime Kuma/Telegram alert on every SSH login, push URL from the `uptime_ssh_login_urls` output of `pangolin_config`; keys silenced by SHA256 fingerprint in `ssh_login_notify_ignored_fingerprints`, never by comment; `ssh_login_notify_enabled: false` removes the hook, an empty URL only warns) |
| `docker.yml` | `docker` | Proxmox Docker VM — installs Docker, `docker_service`, `host_tuning`, `security`, `borgmatic`, `newt`, then every app role (the Beszel hub `beszel`, `victoria_logs` included), plus `beszel_agent`, `mem_report`, `log_agent`, `update_notify`, `cost_report` and, last, `homepage` |
| `pangolin.yaml` | `pangolin` | Hetzner Pangolin VM — Docker, `borgmatic`, `security` hardening, `nat_gateway` (NAT of the private network for flip), `pangolin` role, `beszel_agent`, `log_agent` (both in `compose` mode, no `docker_service`), `update_notify` |
| `pi.yml` | `pi` | Raspberry Pi (Debian 13) — Docker, `docker_service`, `host_tuning` (zram, plus the 4 GiB `dphys-swapfile` overflow behind it via `host_tuning_disk_swap_size_mb`), `security`, `borgmatic`, `newt`, `immich`, `blocky` (the first of the two home DNS resolvers, a container published on the Pi's LAN IP only; `docs/runbooks/dns-blocky.md`), `beszel_agent`, `log_agent`, `mem_report`, `update_notify`, then tasks tagged `legacy_cleanup` keeping the pre-Pangolin certbot/nginx leftovers absent (the hostname is still `reese`, as in its cron mails) |
| `flip.yml` | `flip` | Hetzner flip server (no public IP) — `nat_client` first, then Docker, `docker_service`, `host_tuning`, `security`, `borgmatic`, `newt`, `flip_planning` ×4 (prod, demo, Keycloak demo, public showcase `exemple_planning`), `promptoramix`, `beszel_agent`, `log_agent`, `mem_report`, `update_notify`. Newt credentials come from the `pangolin_config` state (`flip_newt_id`/`flip_newt_secret` outputs), not from SOPS |
| `lxc.yml` | `newt_lxc` | Proxmox Newt LXC — `security` without ufw, auditd or devsec's os_hardening (`host_vars/newt-lxc`: an unprivileged container owns none of them), then `newt_service` (Newt as a plain systemd service, no Docker), `beszel_agent`, `log_agent` and `blocky` in `binary` mode (the second home DNS resolver; the `dns` private resource of `pangolin_config` serves it to phones through the Pangolin client). Credentials of the `proxmox-lxc` site from the `pangolin_config` state (`proxmox_lxc_newt_id`/`proxmox_lxc_newt_secret` outputs), not from SOPS. A fresh LXC first gets `00-setup.yaml --limit newt-lxc -e ansible_user=root` |
| `nas.yml` | `nas` | Ugreen NAS (UGOS Pro, static in `inventory/hosts`) — `docker_service` in system scope (tags `setup,always`: `/etc/systemd/system/dc@.service` run as root, apps under `/volume1/docker`, the UGOS Docker app's shared folder; see `ansible/roles/docker_service/README.md`), then `borgmatic` in a container (tags `backup,setup`, see `ansible/roles/borgmatic/README.md`), then role `nas`: pins `maximumNFSProtocol` in `/etc/nfs.json` (UGOS regenerates `/etc/nfs.conf` from it), writes the homelab NFS exports to `/etc/exports.d/homelab.exports` (`host_vars/nas`, always `sync`, client IPs only) and asserts nfs-server is up with no `async` export, then `beszel_agent`, `log_agent`, `newt` (site `nas`, credentials from the `pangolin_config` state: `nas_newt_id`/`nas_newt_secret` outputs, not SOPS) and `jellyfin` (`dc@jellyfin`, media from the UGOS shared folder `media` mounted `:ro`; the role asserts the share and its library folders before writing anything, under its own tag only). Then `nas_proxy` (TLS front of the NAS: `ansible/roles/nas_proxy/README.md`; Jellyfin's network: `ansible/roles/jellyfin/README.md`), last `kdrive_sync` (`ansible/roles/kdrive_sync/README.md`). Nothing else of UGOS is touched (no 00-setup, security or packages); shared folders are created in the UI. Run by hand only, never by CI (`resolve_docker_tags.py` prints a notice for a role only `nas.yml`, `pve.yml`, `lxc.yml` or `00-setup.yaml` uses: its `MANUAL_PLAYBOOKS`) |
| `pve.yml` | `pve` | Proxmox VE host (static in `inventory/hosts`, root without become through `host_vars/pve`: no sudo there; excluded from `00-setup.yaml`) — `beszel_agent` in `binary` mode with S.M.A.R.T. of `/dev/sda` (the M.2 SATA SSD under every VM and the LXC), `vzdump_restore_test` (`ansible/roles/vzdump_restore_test/README.md`), plus `update_notify` in apt mode (`ansible/roles/update_notify/README.md`), plus `tmpdir: /var/tmp` in `/etc/vzdump.conf` (tag `vzdump`: on the NAS's NFS, an unprivileged LXC's tar cannot open the temporary dir vzdump creates there as root, and the API refuses `tmpdir` to Tofu's token). The rest of the host belongs to Proxmox and `tofu/proxmox`. Reads the `pangolin_config` state (push URL). Run by hand only, never by CI (`MANUAL_PLAYBOOKS` of `resolve_docker_tags.py`) |
| `pc-nas.yml` | `localhost` | the workstation: `--tags mount` / `--tags umount` (with `-K`; no tag does nothing, every task is tagged `never`) of a NAS shared folder over SMB on `/mnt/nas/<share>` (`pc_nas_share`, default `media`; host from the `nas` inventory entry), for ad hoc tests only — no fstab, password prompted (`no_log`) and handed to `mount.cifs` through a root-only `0600` `credentials=` file under `/run` (tmpfs), written by `command` + `stdin` with `ansible_pipelining: true` (a `copy content=` or an unpipelined module stages the secret in `~/.ansible/tmp`, on disk), deleted right after the mount even on failure (`PASSWD_FILE=/dev/stdin` got `STATUS_LOGON_FAILURE`; `PASSWD` would land in `ps` and `run.log`). With the Pangolin client connected, the NAS IP goes through the private resource `nas.sylvain.cloud`, which opens TCP 445 for it (pinned by `pangolin_config`'s tests) |
| `backup.yaml` | `docker,pi,pangolin,flip,nas` then `backups` | reads each host's borgmatic public key, then creates `backup/<host>/.ssh` on the Storage Box and uploads it as that subaccount's `authorized_keys` (see `ansible/roles/borgmatic/README.md`), plus the key of the read-only `restore-test` subaccount into `backup/.ssh/authorized_keys` (read with `tofu output` in `tofu/pangolin`) |

`00-setup.yaml`, `docker.yml`, `flip.yml`, `lxc.yml`, `nas.yml`, `pve.yml` and `pangolin.yaml`/`pi.yml` all read the OpenTofu state for `pangolin_config` from the S3-compatible backend (`homelab-tf-state-sylvain` bucket at `s3.eu-west-par.io.cloud.ovh.net`) to pull Uptime Kuma healthcheck-push URLs as Terraform outputs, then pass them into the relevant roles. The SOPS load and the state read are shared: each playbook's first `pre_tasks` entry imports `ansible/tasks/pangolin_config_outputs.yml`, which sets the `terraform_outputs` fact (`no_log`; the state is downloaded once per run, `run_once`, and the registered result reaches every host). A state that cannot be read fails the play, except in `00-setup.yaml`, the only playbook that sets `pangolin_config_outputs_optional: true`: there `terraform_outputs` falls back to `{}` with a warning, so base setup still runs and `ssh_login_notify` only warns. The playbook then `set_fact`s its own `<var>: "{{ terraform_outputs.<output>.value | default('') }}"` — keep that literal form in the playbook, `tofu/pangolin_config/tests/invariants.tftest.hcl` greps the playbooks for it.

## Config layering

- `ansible/group_vars/all/variables.yml` — shared defaults (`docker_base_path: /opt/apps`, `borgmatic_config_dir`, `newt_endpoint`, SSH user, etc.), plus vendored-role var files (`geerlingguy.docker.yml`). devsec.hardening's variables are not there: the `security` role passes them to `include_role` from its own `security_*` defaults.
- `ansible/host_vars/<host>/` — per-host overrides (`docker`, `pangolin`, `flip`, `pi`, `newt-lxc`, `nas`, `pve`, `backups`). Note this is `host_vars/<hostname>`, matching the dynamic-inventory-generated host name, not a role/group name.
- Ansible collections live in `ansible/collections/ansible_collections/` and Galaxy roles in `ansible/galaxy_roles/`, both populated from `ansible/requirements.yml` (not committed as vendored source — reinstall via `ansible-galaxy install -r requirements.yml` if missing, or set up through mise/CI).
