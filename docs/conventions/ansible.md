# Ansible: playbooks, inventory, config layering

Moved from `AGENTS.md` (agent-facing notes, kept in English); the index there links here.

## Running a specific Ansible playbook

There is no `site.yml`: from `ansible/`, target the playbook for the host group you're changing:

```bash
ansible-playbook 00-setup.yaml   # base host setup (user, packages, starship)
ansible-playbook docker.yml      # Proxmox docker host: all the app roles
ansible-playbook flip.yml        # Hetzner flip server: Flip Planning (prod, demo, Keycloak demo), Promptoramix
ansible-playbook pangolin.yaml   # Pangolin Hetzner VM
ansible-playbook pi.yml          # Raspberry Pi (Immich, Blocky)
ansible-playbook lxc.yml         # Proxmox Newt LXC (site proxmox-lxc, Blocky); by hand only
ansible-playbook nas.yml         # Ugreen NAS (Jellyfin, NAS Traefik, kDrive copy, MediaManager trial); by hand only
ansible-playbook pve.yml         # Proxmox VE host (config backup, Beszel agent, vzdump restore test, update notices, hardening); by hand only
ansible-playbook backup.yaml     # authorizes each host's borgmatic key on its Storage Box subaccount
ansible-playbook test.yaml
```

No `-i`: `ansible.cfg` sets `inventory = ./inventory`, i.e. `proxmox.py`, `hetzner.py` and `hosts` together. `-i inventory/hosts` alone would only know the static hosts (Pi, LXC, NAS, Proxmox host).

Add `--check` for a dry run, `--tags <tag>` to scope to one role/app (e.g. `--tags betisier`), and `-v`/`-vv`/`-vvv` for verbosity. `ansible.cfg` sets `stdout_callback = debug` and logs every run to `ansible/run.log`; fact cache lives in `ansible/facts/`. It also turns SSH pipelining on (`pipelining = True`, one SSH round trip per task, mirrored in Molecule by `ANSIBLE_PIPELINING`), which needs `requiretty` absent from every host's sudoers: check it on any new host (`sudo grep -r requiretty /etc/sudoers /etc/sudoers.d`). Runs go through Mitogen (`strategy = mitogen_linear`, relayed by `ansible/strategy_plugins/mitogen_linear.py`): one Python kept alive per host instead of one started per task, a `--check` of the Pi went from 7 min 43 to 1 min 08. `ANSIBLE_STRATEGY=linear` falls back for one run; an ansible-core bump waits for a Mitogen release that supports it (Renovate note on those PRs). Molecule does not read `ansible.cfg` and stays on `linear`. The Storage Box play of `backup.yaml` also pins `strategy: linear` (no Python on the Box, Mitogen fails there on its first `raw` with « EOF on stream »; a play keyword beats `ANSIBLE_STRATEGY`). A venv without Mitogen (`uv sync` skipped) fails every playbook on an `ImportError` of `ansible_mitogen`: `uv sync`, or `ANSIBLE_STRATEGY=linear`. Mitogen keeps its Python per host and become user for the whole play: a task that changes the process itself (a user added to the `docker` group) is only seen after a `meta: reset_connection`.

**Inventory** is dynamic: `ansible/inventory/proxmox.py` and `ansible/inventory/hetzner.py` read the corresponding `tofu state -json` output (via `tofu show -json` run against `../tofu/proxmox` or `../tofu/pangolin`) to build host lists — so `tofu apply` must be current before an inventory-dependent Ansible run picks up new hosts. Both states are encrypted: without `TF_VAR_state_encryption_passphrase` in the environment (mise loads it: run through `mise exec --` or a mise-activated shell) each script only warns on stderr and its hosts (`docker`, `pangolin`, `flip`…) vanish from the inventory, so a play ends on « no hosts matched ». Same symptom, with « Backend initialization required » in the warning, when a `backend.tf` changed since this checkout's last `init` (`use_lockfile`, 2026-11-11): `mise exec -- tofu -chdir=tofu/<proxmox|pangolin> init -reconfigure`. `ansible/inventory/hosts` holds the static hosts: the Raspberry Pi, the Newt LXC (`newt_lxc` group, host `newt-lxc`; `proxmox.py` only reads VMs), the NAS (`ugreen` group, host `nas`) and the Proxmox host (`proxmox_ve` group, host `pve`). A Hetzner server with no public IPv4 (flip) is emitted by `hetzner.py` with its private IP and a `-o ProxyCommand="ssh … -W %h:%p sylvain@<pangolin public IP>"` that checks the bastion against `ansible/known_hosts` (Pangolin's sshd allows it via `security_ssh_allow_tcp_forwarding: local` in `host_vars/pangolin`); CI does the same (private IP + `ProxyJump=pangolin.sylvain.cloud`, bastion key in the runner's `~/.ssh/config`). A server labelled `role=drill` (the throwaway copy of the docker VM, `tofu/pangolin/drill.tf`) goes into the group `drill` only, with `drill_borg_*` variables from the state outputs and `-o GlobalKnownHostsFile=ansible/known_hosts.drill` (ignored by version control; no `ssh-keyscan`). It is run with `ansible-playbook docker.yml -e drill_target=drill -e docker_drill_key_file=…` (`hosts:` is `docker` without it) and is excluded from `00-setup.yaml`; `drill_mode` (`group_vars/drill/`) switches off Newt, the borgmatic timer and every reporting role: `docs/runbooks/reconstruction-vm-docker.md`. Never point Ansible at `flip.internal`: that Pangolin private resource is served by flip's own Newt, so a play restarting newt or docker there cuts its own connection; it is only for manual access through a Pangolin client.

## Host groups / playbook mapping

| Playbook | Host group | Purpose |
|---|---|---|
| `00-setup.yaml` | `all,!backups,!nas,!pve,!drill` | base setup: apt packages, timezone, `sylvain` user + SSH keys from `keys/*.pub`, starship prompt, `ssh_login_notify` (Uptime Kuma/Telegram alert on SSH logins, push URL from the `uptime_ssh_login_urls` output of `pangolin_config`; a key of `ssh_login_notify_known_fingerprints`, by SHA256 fingerprint and never by comment, gets a low-priority ntfy trace and a journal line instead; role defaults, emptied by `host_vars/newt-lxc`, where every login rings; `ssh_login_notify_enabled: false` removes the hook, an empty URL only warns; `ansible/roles/ssh_login_notify/README.md`) |
| `docker.yml` | `docker` | Proxmox Docker VM — installs Docker, `docker_service`, `host_tuning`, `security`, `borgmatic`, `newt`, then every app role (the Beszel hub `beszel`, `victoria_logs` included), plus `beszel_agent`, `mem_report`, `log_agent`, `update_notify`, `ci_key_audit`, `log_alerts`, `dav_copy` (temporary Nextcloud to Infomaniak copy), `cost_report` and, last, `homepage` |
| `pangolin.yaml` | `pangolin` | Hetzner Pangolin VM — Docker, `borgmatic`, `security` hardening, `nat_gateway` (NAT of the private network for flip), `pangolin` role, `beszel_agent`, `log_agent` (both in `compose` mode, no `docker_service`), `update_notify` |
| `pi.yml` | `pi` | Raspberry Pi (Debian 13) — Docker, `docker_service`, `host_tuning` (zram, plus the 4 GiB `dphys-swapfile` overflow behind it via `host_tuning_disk_swap_size_mb`), `security`, `borgmatic`, `newt`, `immich`, `blocky` (the first of the two home DNS resolvers, a container published on the Pi's LAN IP only; `docs/runbooks/dns-blocky.md`), `beszel_agent`, `log_agent`, `mem_report`, `update_notify`, `smart_check` (NVMe wear, `ansible/roles/smart_check/README.md`), then tasks tagged `legacy_cleanup` keeping the pre-Pangolin certbot/nginx leftovers absent (the hostname is still `reese`, as in its cron mails) |
| `flip.yml` | `flip` | Hetzner flip server (no public IP) — `nat_client` first, then Docker, `docker_service`, `host_tuning`, `security`, `borgmatic`, `newt`, `flip_planning` ×4 (prod, demo, Keycloak demo, public showcase `exemple_planning`), `promptoramix`, `beszel_agent`, `log_agent`, `mem_report`, `update_notify`. Newt credentials come from the `pangolin_config` state (`flip_newt_id`/`flip_newt_secret` outputs), not from SOPS |
| `lxc.yml` | `newt_lxc` | Proxmox Newt LXC — `security` without ufw, auditd or devsec's os_hardening (`host_vars/newt-lxc`: an unprivileged container owns none of them), then `newt_service` (Newt as a plain systemd service, no Docker), `beszel_agent`, `log_agent`, `update_notify` and `blocky` (`beszel_agent`, `log_agent` and `blocky` in `binary` mode; `blocky` is the second home DNS resolver; the `dns` private resource of `pangolin_config` serves it to phones through the Pangolin client). Credentials of the `proxmox-lxc` site from the `pangolin_config` state (`proxmox_lxc_newt_id`/`proxmox_lxc_newt_secret` outputs), not from SOPS. A fresh LXC first gets `00-setup.yaml --limit newt-lxc -e ansible_user=root` |
| `nas.yml` | `nas` | Ugreen NAS (UGOS Pro, static in `inventory/hosts`) — `docker_service` in system scope (tags `setup,always`: `/etc/systemd/system/dc@.service` run as root, apps under `/volume1/docker`, the UGOS Docker app's shared folder; see `ansible/roles/docker_service/README.md`), then `borgmatic` in a container (tags `backup,setup`, see `ansible/roles/borgmatic/README.md`), then role `nas`: pins `maximumNFSProtocol` in `/etc/nfs.json` (UGOS regenerates `/etc/nfs.conf` from it), writes the homelab NFS exports to `/etc/exports.d/homelab.exports` (`host_vars/nas`, always `sync`, client IPs only) and asserts nfs-server is up with no `async` export, then `beszel_agent`, `log_agent`, `newt` (site `nas`, credentials from the `pangolin_config` state: `nas_newt_id`/`nas_newt_secret` outputs, not SOPS) and `jellyfin` (`dc@jellyfin`, media from the UGOS shared folder `media` mounted `:ro`; the role asserts the share and its library folders before writing anything, under its own tag only), `immich_ml` (`dc@immich_ml`, Immich's machine learning with OpenVINO on the iGPU, called first by the Pi's Immich over the LAN, port 3003 with no authentication: `ansible/roles/immich_ml/README.md`; an Immich bump is deployed there by hand). Then `nas_proxy` (TLS front of the NAS, after `jellyfin` whose network it joins; creates `mediamanager_proxy`: `ansible/roles/nas_proxy/README.md`; Jellyfin's network: `ansible/roles/jellyfin/README.md`), then `kdrive_sync` (`ansible/roles/kdrive_sync/README.md`), `mediamanager` (trial, `dc@mediamanager`, after `nas_proxy` whose `mediamanager_proxy` network it joins: `ansible/roles/mediamanager/README.md`), last `smart_check` (weekly S.M.A.R.T. alert on a rise, UGOS's own `smartctl`, state under `docker_base_path`: `ansible/roles/smart_check/README.md`). Nothing else of UGOS is touched (no 00-setup, security or packages); shared folders are created in the UI. Run by hand only, never by CI (`resolve_docker_tags.py` prints a notice for a role only `nas.yml`, `pve.yml`, `lxc.yml`, `pc-support.yml` or `00-setup.yaml` uses: its `MANUAL_PLAYBOOKS`) |
| `pve.yml` | `pve` | Proxmox VE host (static in `inventory/hosts`, root without become through `host_vars/pve`: no sudo there; excluded from `00-setup.yaml`) — `borgmatic` and `pve_config_backup` (nightly Borg copy of pmxcfs's `config.db` and the network files to the host's own Storage Box subaccount, skipped while the SOPS key `backup_storage_box_subaccounts` has no `pve` entry: `ansible/roles/pve_config_backup/README.md`), `beszel_agent` in `binary` mode with S.M.A.R.T. of `/dev/sda` (the M.2 SATA SSD under every VM and the LXC), `log_agent` in `binary` mode (skipped while the SOPS dict `victoria_logs_agent_passwords` has no `pve` key) and `ssh_login_notify` (monitor « SSH pve », `ssh_login_hosts`; it reads its URL itself since `00-setup.yaml` excludes pve), `vzdump_restore_test` (`ansible/roles/vzdump_restore_test/README.md`), plus `update_notify` in apt mode (`ansible/roles/update_notify/README.md`), `smart_check` (SSD wear and sector alerts on a rise, `ansible/roles/smart_check/README.md`), `thin_pool_check` (down in Uptime Kuma when the LVM thin pool reaches 85 %, `ansible/roles/thin_pool_check/README.md`), then `pve_hardening` (sshd key-only, host-level PVE firewall with 22/8006 from the LAN, `pve-enterprise` repo and unused SDN zone removed; one sub-tag per part, applied with a rescue session open: `ansible/roles/pve_hardening/README.md`), plus `tmpdir: /var/tmp` in `/etc/vzdump.conf` (tag `vzdump`: on the NAS's NFS, an unprivileged LXC's tar cannot open the temporary dir vzdump creates there as root, and the API refuses `tmpdir` to Tofu's token). The rest of the host belongs to Proxmox and `tofu/proxmox` (no `security` role: ufw and devsec would fight `pve-firewall`). Reads the `pangolin_config` state (push URL). Run by hand only, never by CI (`MANUAL_PLAYBOOKS` of `resolve_docker_tags.py`) |
| `pc-nas.yml` | `localhost` | the workstation: `--tags mount` / `--tags umount` (with `-K`; no tag does nothing, every task is tagged `never`) of a NAS shared folder over SMB on `/mnt/nas/<share>` (`pc_nas_share`, default `media`; host from the `nas` inventory entry), for ad hoc tests only — no fstab, password prompted (`no_log`) and handed to `mount.cifs` through a root-only `0600` `credentials=` file under `/run` (tmpfs), written by `command` + `stdin` with `ansible_pipelining: true` (a `copy content=` or an unpipelined module stages the secret in `~/.ansible/tmp`, on disk), deleted right after the mount even on failure (`PASSWD_FILE=/dev/stdin` got `STATUS_LOGON_FAILURE`; `PASSWD` would land in `ps` and `run.log`). With the Pangolin client connected, the NAS IP goes through the private resource `nas.sylvain.cloud`, which opens TCP 445 for it (pinned by `pangolin_config`'s tests) |
| `pc-support.yml` | `localhost` | the workstation, remote support POC (`-K`, passwords prompted, `no_log`): `newt_service` (site `pc-sylvain`, credentials from the `pc_sylvain_newt_*` outputs of the `pangolin_config` state), GNOME Remote Desktop RDP system daemon (remote login from boot, self-signed TLS, port pinned) and VNC user service (screen sharing of the open session; view-only turned off, port pinned), credentials handed to `grdctl` on stdin, never as arguments; a firewalld REJECT of 5900 and 3389 in every active zone (`FedoraWorkstation` opens 1025-65535 to the LAN), Newt reaching them on `127.0.0.1`. Run by hand only (`MANUAL_PLAYBOOKS`); the Pangolin side is `tofu/pangolin_config/remote_support.tf`; setup, tests and teardown: `docs/runbooks/support-a-distance.md` |
| `backup.yaml` | `docker,pi,pangolin,flip,nas,pve` then `backups` | reads each host's borgmatic public key, then creates `backup/<host>/.ssh` on the Storage Box and uploads it as that subaccount's `authorized_keys` (see `ansible/roles/borgmatic/README.md`), plus the key of the read-only `restore-test` subaccount into `backup/.ssh/authorized_keys` (read with `tofu output` in `tofu/pangolin`) |

`00-setup.yaml`, `docker.yml`, `flip.yml`, `lxc.yml`, `nas.yml`, `pve.yml` and `pangolin.yaml`/`pi.yml` all read the outputs of the `tofu/pangolin_config` module (Uptime Kuma healthcheck-push URLs, Newt and OIDC credentials…), then pass them into the relevant roles. The SOPS load and the read are shared: each playbook's first `pre_tasks` entry imports `ansible/tasks/pangolin_config_outputs.yml`, which runs `tofu -chdir=tofu/pangolin_config output -json -no-color` on localhost (`command`, `no_log`, `run_once`, the result reaches every host) and sets the `terraform_outputs` fact from its JSON (`{name: {value, type, sensitive}}`, hence `terraform_outputs.<name>.value`). The module must therefore be **initialised** on the machine that runs Ansible (`mise run provider-fork`, then `mise exec -- tofu -chdir=tofu/pangolin_config init`; the CI does it in « Init tofu/pangolin_config to read its outputs »), with `tofu` on the `PATH` (run Ansible through `mise exec --`). Nothing reaches the command line: the S3 credentials of the state (`state_s3_*` of `secrets/ansible.sops.yaml`, a read-only user) and the state passphrase go through the command's environment. The passphrase is `tofu_state_passphrase` (a key of `secrets/ansible.sops.yaml`, because the CI's Age key cannot open the root `secrets.sops.yaml`) or, failing that, the `TF_VAR_pangolin_config_state_passphrase` that mise exports (same value, dedicated to this state: not the common `state_encryption_passphrase`). The state is encrypted (migrated on 2026-11-12, no fallback), so a missing or wrong passphrase fails the read. An out-of-date checkout (the pre-phase-1 task, which read the state as JSON from S3) gets `terraform_outputs = {}` now that the state is encrypted: pull `main` before any run. A read that fails (module not initialised, S3, passphrase, `tofu` missing) or returns no output at all (`{}`: empty or missing state; `TF_WORKSPACE=default` is forced) fails the play with the command to run, except in `00-setup.yaml`, the only playbook that sets `pangolin_config_outputs_optional: true`: there `terraform_outputs` falls back to `{}` with a warning, so base setup still runs and `ssh_login_notify` only warns. The playbook then `set_fact`s its own `<var>: "{{ terraform_outputs.<output>.value | default('') }}"` — keep that literal form in the playbook, `tofu/pangolin_config/tests/invariants.tftest.hcl` greps the playbooks for it.

## Config layering

- `ansible/group_vars/all/variables.yml` — shared defaults (`docker_base_path: /opt/apps`, `borgmatic_config_dir`, `newt_endpoint`, SSH user, etc.), plus vendored-role var files (`geerlingguy.docker.yml`). devsec.hardening's variables are not there: the `security` role passes them to `include_role` from its own `security_*` defaults.
- `ansible/host_vars/<host>/` — per-host overrides (`docker`, `pangolin`, `flip`, `pi`, `newt-lxc`, `nas`, `pve`, `backups`). Note this is `host_vars/<hostname>`, matching the dynamic-inventory-generated host name, not a role/group name.
- Ansible collections live in `ansible/collections/ansible_collections/` and Galaxy roles in `ansible/galaxy_roles/`, both populated from `ansible/requirements.yml` (not committed as vendored source — reinstall via `ansible-galaxy install -r requirements.yml` if missing, or set up through mise/CI).
