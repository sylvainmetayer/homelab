# OpenTofu: backends and state encryption

Moved from `AGENTS.md` (agent-facing notes, kept in English); the index there links here.

Per-module notes live in each `tofu/<module>/README.md`; tests in `docs/conventions/tests.md`.

- All backends are S3-compatible object storage (`homelab-tf-state-sylvain` bucket at `https://s3.eu-west-par.io.cloud.ovh.net`), not native AWS — `backend "s3" { endpoints = { s3 = ... } }`.
- Every state except `tofu/pangolin_config`'s is encrypted (`pangolin`, `github`, `s3_state`, `keepass_backup`, and, migrated on 2026-11-11, `proxmox`, `site`, `ref`, `1y`, `planning`, `dns`, `keycloak_demo_planning_kc`) by OpenTofu (`encryption.tf`: AES-GCM, PBKDF2 key from `var.state_encryption_passphrase`, i.e. `TF_VAR_state_encryption_passphrase` from the root `secrets/secrets.sops.yaml` that mise loads). `tofu/dns` decrypts `tofu/pangolin`'s state for its `terraform_remote_state.pangolin` (`remote_state_data_sources`), with the same passphrase as its own state. `tofu/pangolin_config` keeps its state in clear too, because Ansible reads it on S3, and for that reason reads **no** `data "sops_file"` and no `terraform_remote_state`: a data source is written whole into the state, so its secrets come in as `TF_VAR_*` variables that `mise.toml` maps from the SOPS keys, and only the values a resource stores reach the state (`tofu/pangolin_config/README.md`, « Secrets and state »). `ansible/inventory/hetzner.py` runs `tofu show` in `tofu/pangolin`, so it needs the same environment. Tests pass a dummy passphrase in their `variables {}` block. There is no `unencrypted` fallback any more for the first four (migrated on 2026-10-23) nor for the six others (rewritten encrypted by an `apply -refresh-only` on 2026-11-11, fallback removed after); `tofu/keycloak_demo_planning_kc` alone keeps one (`method "unencrypted" "migrate"`, a `fallback` in the `state` and `plan` blocks) because its state could not be migrated: its demo Keycloak answered 404 at the provider's login. Once the demo Keycloak is reachable, run `mise exec -- tofu -chdir=tofu/keycloak_demo_planning_kc apply -refresh-only`, then a follow-up PR removes the fallback. `ansible/inventory/proxmox.py` runs `tofu show` in `tofu/proxmox` like `hetzner.py` does in `tofu/pangolin`: both need `TF_VAR_state_encryption_passphrase` in the environment (run Ansible through `mise exec --`). Nothing else reads these states: a state in clear, or encrypted with another passphrase, is refused. The state keys in the bucket are `homelab/<module>.tfstate` for eleven modules; `tofu/dns` alone is under `dns/terraform.tfstate`, left as it is (it would matter only if a per-prefix S3 policy were ever introduced).
- **State lock**: every S3 backend sets `use_lockfile = true` (native lock: an object `<key>.tflock` written with a conditional write, `If-None-Match`, which OVH Object Storage supports; tried on `tofu/1y` on 2026-11-11, plan and apply passed, then generalised). A second run on the same module is refused with `Error acquiring the state lock`; `plan` takes the lock too. Still one apply at a time per module, whoever runs it (Sylvain or an agent). The option changes the backend configuration: run `tofu init -reconfigure` once per checkout after pulling it (the state does not move), in every initialised module including `tofu/pangolin` and `tofu/proxmox`: until then `tofu init` stops on « Backend configuration changed », `plan` and `show` on « Backend initialization required », and so do the `hetzner.py` and `proxmox.py` inventories. A lock left by a killed run (`homelab/<module>.tfstate.tflock`, `dns/terraform.tfstate.tflock` for `tofu/dns`) blocks the next ones until `tofu force-unlock <ID>` (ID in the error), only once nobody else is running.
- **State and KeePass buckets**: `tofu/s3_state`'s bucket holds every state, its own included, and `tofu/keepass_backup`'s bucket the KeePass backups; both carry `lifecycle { prevent_destroy = true }`.
