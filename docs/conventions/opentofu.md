# OpenTofu: backends and state encryption

Moved from `AGENTS.md` (agent-facing notes, kept in English); the index there links here.

Per-module notes live in each `tofu/<module>/README.md`; tests in `docs/conventions/tests.md`.

- All backends are S3-compatible object storage (`homelab-tf-state-sylvain` bucket at `https://s3.eu-west-par.io.cloud.ovh.net`), not native AWS — `backend "s3" { endpoints = { s3 = ... } }`.
- The states of `tofu/pangolin`, `tofu/github`, `tofu/s3_state` and `tofu/keepass_backup` are encrypted by OpenTofu (`encryption.tf`: AES-GCM, PBKDF2 key from `var.state_encryption_passphrase`, i.e. `TF_VAR_state_encryption_passphrase` from the root `secrets/secrets.sops.yaml` that mise loads). `tofu/dns` decrypts `tofu/pangolin`'s state for its `terraform_remote_state.pangolin` (`remote_state_data_sources`) and keeps its own state in clear. `tofu/pangolin_config` keeps its state in clear too, because Ansible reads it on S3, and for that reason reads **no** `data "sops_file"` and no `terraform_remote_state`: a data source is written whole into the state, so its secrets come in as `TF_VAR_*` variables that `mise.toml` maps from the SOPS keys, and only the values a resource stores reach the state (`tofu/pangolin_config/README.md`, « Secrets and state »). `ansible/inventory/hetzner.py` runs `tofu show` in `tofu/pangolin`, so it needs the same environment. Tests pass a dummy passphrase in their `variables {}` block. There is no `unencrypted` fallback any more (the four migrated on 2026-10-23): a state in clear, or encrypted with another passphrase, is refused. The state keys in the bucket are `homelab/<module>.tfstate` for eleven modules; `tofu/dns` alone is under `dns/terraform.tfstate`, left as it is (it would matter only if a per-prefix S3 policy were ever introduced).
