# OpenTofu: backends and state encryption

Moved from `AGENTS.md` (agent-facing notes, kept in English); the index there links here.

Per-module notes live in each `tofu/<module>/README.md`; tests in `docs/conventions/tests.md`.

- All backends are S3-compatible object storage (`homelab-tf-state-sylvain` bucket at `https://s3.eu-west-par.io.cloud.ovh.net`), not native AWS — `backend "s3" { endpoints = { s3 = ... } }`.
- Every state except `tofu/pangolin_config`'s is encrypted (`pangolin`, `github`, `s3_state`, `keepass_backup`, and, migrated by the `fallback` described below, `proxmox`, `site`, `ref`, `1y`, `planning`, `keycloak_demo_planning_kc`, `dns`) by OpenTofu (`encryption.tf`: AES-GCM, PBKDF2 key from `var.state_encryption_passphrase`, i.e. `TF_VAR_state_encryption_passphrase` from the root `secrets/secrets.sops.yaml` that mise loads). `tofu/dns` decrypts `tofu/pangolin`'s state for its `terraform_remote_state.pangolin` (`remote_state_data_sources`), with the same passphrase as its own state. `tofu/pangolin_config` keeps its state in clear too, because Ansible reads it on S3, and for that reason reads **no** `data "sops_file"` and no `terraform_remote_state`: a data source is written whole into the state, so its secrets come in as `TF_VAR_*` variables that `mise.toml` maps from the SOPS keys, and only the values a resource stores reach the state (`tofu/pangolin_config/README.md`, « Secrets and state »). `ansible/inventory/hetzner.py` runs `tofu show` in `tofu/pangolin`, so it needs the same environment. Tests pass a dummy passphrase in their `variables {}` block. There is no `unencrypted` fallback any more for the first four (migrated on 2026-10-23); the seven others keep one (`method "unencrypted" "migrate"`, a `fallback` in the `state` and `plan` blocks) until their first apply has rewritten the state encrypted, then a follow-up PR removes it. `ansible/inventory/proxmox.py` runs `tofu show` in `tofu/proxmox` like `hetzner.py` does in `tofu/pangolin`: both need `TF_VAR_state_encryption_passphrase` in the environment (run Ansible through `mise exec --`). Nothing else reads these states: a state in clear, or encrypted with another passphrase, is refused. The state keys in the bucket are `homelab/<module>.tfstate` for eleven modules; `tofu/dns` alone is under `dns/terraform.tfstate`, left as it is (it would matter only if a per-prefix S3 policy were ever introduced).
- **State lock**: no backend but `tofu/1y`'s sets `use_lockfile = true` (a trial: OVH Object Storage documents conditional writes, `If-None-Match`, which the native S3 lock needs; if the trial holds, add it to the others). Without it **two applies at once on the same module are not refused**: the last writer wins. One apply at a time, per module, whoever runs it (Sylvain or an agent); `Error acquiring the state lock` is only meaningful on `1y`. Adding or removing `use_lockfile` changes the backend configuration: `tofu init -reconfigure` (the state does not move). `plan` takes the lock too, so a refused conditional write shows there, not at `init`; a lock left by a killed run (`homelab/1y.tfstate.tflock`) blocks the next ones until `tofu force-unlock <ID>` (ID in the error), only once nobody else is running.
- **State and KeePass buckets**: `tofu/s3_state`'s bucket holds every state, its own included, and `tofu/keepass_backup`'s bucket the KeePass backups; both carry `lifecycle { prevent_destroy = true }`.
