# Hosted apps

Each app is an Ansible role (`ansible/roles/<role>`) deployed by the playbook of its host, and its Pangolin route is an entry in `tofu/pangolin_config/website_<name>.tf`. Unless noted, Pangolin asks for SSO login before it lets a request through.

|---|---|---|---|
| [Homepage](https://gethomepage.dev/) | `homepage` | Docker VM | Start page on `home.sylvain.cloud`: one link per public app, generated from `local.websites` (the `homepage` field of each entry, `homepage_links` output read by `docker.yml`), plus Jellyfin and the Pangolin dashboard. Links only (no widget, API key or Docker socket), so nothing to back up |
| [FreshRSS](https://freshrss.org/) | `rss` | Docker VM | RSS reader |

| [Paperless-ngx](https://docs.paperless-ngx.com/) | `paperless_ngx` | Docker VM | Scanned documents with OCR. **Paused** since October 2026 (`paperless_enabled: false`): stopped, not backed up, Pangolin resource disabled, data and borg repository kept; see [runbooks/app-en-pause.md](runbooks/app-en-pause.md) to resume |

Sign-up closed (`papra_registration_enabled: false`): the first account is made by reopening it for one run (`-e papra_registration_enabled=true`). If it does not convince: `remove-app` skill |

| [ntfy](https://ntfy.sh/) | `ntfy` | Docker VM | Push notifications of the homelab on `ntfy.sylvain.cloud`, relayed to the phones through ntfy.sh (`upstream-base-url`: it only sees message ids). Nothing without an account (`auth-default-access: deny-all`); accounts, grants and tokens declared in `server.yml` by the role: `sylvain` (phone app, read-write on every topic) and one write-only token per producer on its own topic (`uptime-kuma`, `scripts`, `github`: the CI workflows, Renovate digest and Trivy). The web interface is behind the SSO; `/`, each producer topic and `/*/json`, `/*/ws`, `/*/auth` are open without SSO, from any country, for the apps and publishers, guarded by ntfy's own auth. | [VictoriaLogs](https://docs.victoriametrics.com/victorialogs/) | `victoria_logs` | Docker VM | Centralised logs of every host, 30 days, queried in LogsQL on `logs.sylvain.cloud/select/vmui/`: behind the SSO, then vmauth's own account. vmauth (`victoria-logs-auth`) is the only way in, also published on the LAN (192.168.1.216:9428) for the agents, each with a write-only account. One Vector agent per host (`log_agent`: docker, pi, pangolin with Traefik's access log and CrowdSec, flip, newt-lxc, NAS) ships journald and container logs; pangolin and flip through Pangolin (PASS on `/insert/jsonline` plus a per-agent access token). No backup: logs are reproducible |

No public resource, no UI: the allowlist is a role variable. See [runbooks/dns-blocky.md](runbooks/dns-blocky.md) |

| [Pangolin](https://pangolin.net/) | `pangolin` | Pangolin VM | The reverse proxy itself and its dashboard |
| [Jellyfin](https://jellyfin.org/) | `jellyfin` | NAS | Media server (films, series, music, books, audiobooks from the `media` shared folder, read-only), Quick Sync transcoding. Not public, one name everywhere: **`https://media.sylvain.cloud`**, with or without `:8443`, at home and outside with the Pangolin client (role `jellyfin`; the private resource of that alias, TCP 443 and 8443, served by the NAS's own Newt, site `nas`). Without a port at home only while UGOS's HTTPS redirect setting stays unticked; `:8443` never depends on it. The public A record points at the NAS's LAN IP (`tofu/dns/media.tf`); the NAS's Traefik (role `nas_proxy`, `dc@nas_proxy`, container `nas-proxy`) terminates TLS with a Let's Encrypt certificate (DNS-01, OVH key `nas_ovh_*`), listening on 443 and 8443; 8443 is published by Docker, the host's 443 is taken by a relay container in host networking (`nas-proxy-443`, PROXY protocol), so a 443 grabbed back by UGOS's nginx only breaks the URL without a port. Fallback: `http://192.168.1.137:8096` on the LAN. Jellyfin's "Known proxies" must hold Traefik's fixed IP on Jellyfin's `media` network, `172.30.96.10`. Jellyfin accounts of its own, no SSO. User guide (apps, casting, file naming, transcoding, ffmpeg): [media.md](media.md). **Not backed up yet**: its config and database (`/volume1/docker/jellyfin/config`) wait for borgmatic on the NAS; the media are only protected by the RAID 1 and the Btrfs snapshots |
| [rclone](https://rclone.org/) | `kdrive_sync` | NAS | Not an app: a nightly one-way copy of kDrive (WebDAV) into the `kdrive` shared folder, `rclone copy` only (nothing is ever deleted on the NAS; a file replaced in kDrive keeps its previous version under `versions/`), `kdrive-sync.timer` at 04:00, monitor « kDrive vers NAS ». Not in borg (opt-in). Setup and recovery: [runbooks/kdrive-nas.md](runbooks/kdrive-nas.md) |

The NAS admin page and Proxmox are not public: they are Pangolin private resources (`nas.sylvain.cloud`, `pve.internal`, `tofu/pangolin_config/private_resources.tf`), served by the Newt LXC. The NAS admin page (UGOS) is **`https://nas.sylvain.cloud`** (or `:8443`) at home and through the Pangolin client, the same NAS Traefik in front of UGOS's nginx (public A record to the NAS's LAN IP, `tofu/dns/nas.tf`); fallback `http://192.168.1.137:9999`.

This table is the reference list of the apps; AGENTS.md points here instead of repeating it. The playbooks are `ansible/docker.yml` (Docker VM), `ansible/pi.yml` (Raspberry Pi), `ansible/flip.yml` (flip), `ansible/pangolin.yaml` (Pangolin VM), `ansible/lxc.yml` (the Newt LXC, no app) and `ansible/nas.yml` (the NAS, run by hand: NFS exports, the Beszel agent, its Newt, Jellyfin, the NAS's Traefik, `nas_proxy`, and the kDrive copy, `kdrive_sync`). To add or remove an app, see the `new-app` and `remove-app` skills under `.claude/skills/` and the matching sections of [AGENTS.md](../AGENTS.md).
