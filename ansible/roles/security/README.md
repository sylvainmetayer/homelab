# Role `security`

Moved from `AGENTS.md` (agent-facing notes, kept in English); the index there links here.

## Host hardening

- Host hardening (`security` role, on pangolin, flip, docker and pi, and on the Newt LXC without ufw, auditd and os_hardening): ufw rules, fail2ban (journal backend), unattended-upgrades and a send-only msmtp relay (Infomaniak account `pangolin_smtp_*`, root aliased to `pangolin_le_email`; it replaces the exim4 that logwatch used to pull) are in-house. sshd and OS hardening come from `devsec.hardening` (os_hardening + ssh_hardening, pinned in `requirements.yml`) on every host running the role; there is no in-house sshd drop-in or sysctl hardening path any more. devsec is applied partially: `security_devsec_sysctl_overwrite` keeps `ip_forward` at 1 (Docker, Pangolin's NAT), `rp_filter` loose and IPv6 forwarding at 1 as Docker sets it, and the role asserts it before devsec reloads its sysctl (immediately, unlike the role's own boot-time file: `disable_ipv6` therefore stays in the boot-only `99-hardening.conf`; `fs.file-max` is set on no path: kernel default, reached only after a reboot on a host that booted with the old 65535, Pangolin included); `ssh_client_hardening` stays off (borgmatic's SSH client); AllowTcpForwarding comes from `security_ssh_allow_tcp_forwarding` (`local` on the bastion). The algorithms sshd offers are ssh-audit's « Hardened Debian 13 » (`security_ssh_*` defaults handed to devsec: post-quantum kex only, etm MACs, ed25519 the only host key, the others deleted from `/etc/ssh`; clients that break: `docs/runbooks/ssh-refuse-apres-durcissement.md`), pinned, exact match, by the ssh-audit policy `ansible/molecule/security/files/ssh-audit-policy.txt`: checked by the verify of every `security*` scenario that replays the role, i.e. all but `security_lan` (`ansible/molecule/security/tasks/verify_ssh_audit.yml`, ssh-audit baked into the Molecule image) and on the real hosts from the LAN by `mise run ssh-audit`; a devsec or OpenSSH bump that changes them fails Molecule until the policy is updated. devsec skips sysctl inside containers, so Molecule cannot prove the kernel values — only the overwrite.
- `systemd-ssh-generator` (systemd 257) is masked (`/etc/systemd/system-generators/systemd-ssh-generator` → `/dev/null`): it would add sshd sockets on AF_UNIX and AF_VSOCK, none used here, and on the VMs, whose `/dev/vsock` has no CID, it failed at every boot and daemon-reload (`Failed to query local AF_VSOCK CID`, priority err). sshd is reached over TCP only.

## LAN hosts (Pi, Docker VM)

- SSH access to the Raspberry Pi and the Docker VM is local-network only: they are LAN hosts, their `security` host_vars open 22/tcp to `192.168.1.0/24` only (the `from` of `security_ufw_allowed_ports`), never ban the LAN (CI arrives through the newt LXC, 192.168.1.200), whitelist `vfat` for devsec (`/boot/efi`, `/boot/firmware`) and reboot after kernel updates at 05:00 (docker) and 05:30 (pi). The Pi's arm64 kernel caps `vm.mmap_rnd_bits` at 24 (`security_devsec_sysctl_host`). Root no longer logs in over SSH anywhere: the Immich remote worker mounts the Pi's library as `sylvain` with a sudo SFTP server (`compose/immich/README.md`). Docker-published ports bypass ufw, so the Pi's Immich and timelapse ports, and Blocky's 53 (published on the Pi's LAN IP only), stay reachable from the LAN; its Postgres and Valkey are published on 127.0.0.1 only, except while the remote Immich worker runs (`immich_remote_worker`, `immich` role).
