# Role `update_notify`

Moved from `AGENTS.md` (agent-facing notes, kept in English); the index there links here.

Part of `pve.yml` (by hand), `docker.yml`, `pi.yml`, `flip.yml` and `pangolin.yaml` (rows in `docs/conventions/ansible.md`), apt only.

`update_notify` (tag `update_notify`): every Monday morning `update-notify.timer` runs `apt-get update` and an `apt-get -s dist-upgrade` simulation, never installs anything, and publishes the pending list to ntfy topic `scripts` (`ntfy_scripts_token`) only when something is pending: security first, then Docker (`docker-*`, `containerd*`, or a `Docker` origin), Proxmox and kernel packages, then the rest, plus a line when Docker is pending (its upgrade restarts every container of the host) and a pending reboot when a newer kernel of the running flavour is installed; priority high when a Debian-Security update waits. Every run pushes up (summary) or down (apt or ntfy failure) to the host's monitor « Mises à jour <host> » (`tofu/pangolin_config/cron_updates.tf`, one `for_each` entry per host, output `uptime_cron_<host>_updates_url`, `set_fact`'d by each playbook in the literal form `tofu/pangolin_config/tests/invariants.tftest.hcl` greps for). Why on the four `unattended-upgrades` hosts too: it installs Debian-Security only, and Docker is deliberately left to a manual daytime upgrade (a `dockerd` restart restarts every app). Times are staggered per host through the role entry's `vars:` (`update_notify_schedule`: pve 08:00, docker 08:30, pi 08:45, flip 09:00, pangolin 09:15). Procedure: `docs/runbooks/mises-a-jour-hotes.md`.
