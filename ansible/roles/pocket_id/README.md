# Role `pocket_id`

Pocket ID, fournisseur OIDC à passkeys (`id.sylvain.cloud`), sur la VM Pangolin ([ADR 0030](../../../docs/adr/0030-pocket-id-fournisseur-identite-pilote.md), procédure et secours : [docs/runbooks/pocket-id.md](../../../docs/runbooks/pocket-id.md)).

- **Hors du mur SSO.** Le conteneur `pocket-id` (image `ghcr.io/pocket-id/pocket-id`, tag et digest, jamais `latest` : Pocket ID migre sa base au démarrage et ne revient pas en arrière) rejoint le réseau externe `pangolin` créé par la pile de Pangolin, où le Traefik de Pangolin l'atteint (`http://pocket-id:1411`). Le routeur est dans la configuration du rôle `pangolin` (`traefik_dynamic_config.yml.j2`, `pangolin_idp_host`), sans Badger, avec une limite de débit par IP ; il ne remplace ni ne touche aucune autre route. Jamais une ressource Pangolin ni un label Docker. Aucun port publié.
- **Rendu seulement avec la clé SOPS `pocket_id_encryption_key`** (`ansible.sops.yaml`, 16 octets au moins). Sans elle, le rôle le dit et ne fait rien, et `host_vars/pangolin` laisse `pangolin_idp_host` vide : pas de routeur. Dans le rôle, `pocket_id_enc_key` la lit (une clé SOPS ne porte jamais le nom d'une variable que le rôle pose).
- **`pocket_id_setup_phase`** (`host_vars/pangolin`, `true` au départ) : le routeur n'admet que `home_ip`. La page `/setup` crée le premier administrateur pour qui arrive le premier (et deux requêtes concurrentes en ont créé plusieurs : GHSA-x6w5-6mr5-mxrx). Passer à `false` après le premier compte, `pangolin.yaml --tags pangolin`.
- **Durcissement** : image `-distroless` (ni shell ni entrypoint : `exec` ne lance que `/app/pocket-id`), `user` 65532, `read_only`, `cap_drop: ALL`, `no-new-privileges`, `tmpfs` sur `/tmp` (guide de durcissement de Pocket ID). `VERSION_CHECK_DISABLED` (Renovate suit les versions), `LOG_JSON` ; les liens `/lc/<code>` et leur échange `/api/one-time-access-token/<code>` sont masqués par `log_agent` avant VictoriaLogs. Pas testé avant le premier déploiement, Molecule ne tirant aucune image : repli au runbook. `mem_limit: 256m`, pas mesuré (la VM Pangolin a 4 Gio, dont 2,5 Gio plafonnés pour Pangolin).
- **Sans compose via `dc@`** : Pangolin n'a pas `docker_service`. `docker compose up -d --remove-orphans` (comme `beszel_agent` en mode `compose`), puis la restart policy. `pocket_id_compose_up: false` l'évite (Molecule).
- **Sauvegarde** : gabarit partagé du rôle `borgmatic` (`tasks_from: app.yml`), le dépôt `pocket_id` du sous-compte de Pangolin ; `data/` entier, copie SQLite par le crochet `sqlite3` du gabarit, jamais la base vive. La base n'existe qu'après le premier démarrage : le premier déploiement ne la trouve pas, le second la copie. Entrée `pocket_id` du test de restauration (`.github/restore-test/apps.json`, tables `users` et `oidc_clients` : noms à confirmer à la première exécution), moniteur push `Backup Pocket ID` (`uptime_backup_pocket_id_url`, `tofu/pangolin_config/pocket_id.tf`), moniteur HTTP `Pocket ID` sur le document de découverte OIDC.
- **Lieux approximatifs** (journal d'audit) : `GEOLITE_DB_PATH` vers `GeoLite2-City.mmdb` du dossier `pocket_id_geoip_dir` (`/opt/geoip`), monté en lecture seule et tenu à jour par `geoipupdate.service` du rôle `pangolin` (même compte MaxMind, aucune clé chez Pocket ID). Pocket ID surveille le dossier et recharge la base seul. L'IP vient de `X-Forwarded-For` (`TRUST_PROXY`). Rôle `pangolin` avant `pocket_id` (`pangolin.yaml`) : la base existe avant le conteneur.
- **Renovate** : hors de la liste d'automerge (une base qui migre, un IdP). Tag en v2 ; une v3 est une montée majeure.
- **Clés SOPS** et leur entrée dans `secrets/secrets-rotation.yaml` : `pocket_id_encryption_key` (`ansible.sops.yaml`, `application`, tournée seulement par la procédure de Pocket ID) et `pocket_id_static_api_key` (dans `ansible.sops.yaml` et `secrets.sops.yaml`, même valeur : le rôle la pose en `STATIC_API_KEY`, clé d'administration par laquelle `tofu/pangolin_config/pocket_id.tf` déclare les clients OIDC et le groupe `homebox`). Les secrets des clients ne sont pas dans SOPS : `random_password` du state de `pangolin_config`.
- **Configuration applicative par l'env** (`UI_CONFIG_DISABLED=true`) : nom, couleur, inscription par lien (`withToken`), groupes des nouveaux comptes (`SIGNUP_DEFAULT_USER_GROUP_IDS` : BentoPDF, Enclosed, PairDrop, identifiants lus dans la sortie Tofu `pocket_id_default_group_ids`), profil modifiable par l'admin seul (`ALLOW_OWN_ACCOUNT_EDIT=false` : sinon un membre prendrait l'e-mail d'un autre et son compte dans les applis qui lient par e-mail sans regarder `email_verified`, Immich, Karakeep, MediaManager), SMTP, alertes de connexion (`browserRecognition`), code de connexion par e-mail de l'admin, rappel d'expiration des clés d'API, vérification d'e-mail (`optional`), dans `defaults/main.yml`. La page « Application Configuration » est en lecture seule ; un réglage non déclaré revient au défaut. SMTP : le compte Infomaniak de msmtp (`pangolin_smtp_user`, `pangolin_smtp_pass`), sans nouvelle clé SOPS ; sans `pangolin_smtp_user` ou sans `pangolin_smtp_pass`, aucune variable SMTP ni d'e-mail. Noms tirés du code de la v2.19.1 (`appconfig/model.go`), la doc des variables ayant du retard : à revoir à chaque montée de version.
