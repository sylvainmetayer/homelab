# Role `pangolin`

Moved from `AGENTS.md` (agent-facing notes, kept in English); the index there links here.

## Response headers

- `security-headers@file` (`traefik_dynamic_config.yml.j2`) sits first on the `websecure` entrypoint, ahead of `crowdsec@file` and of every router's own middlewares (Badger included), so it covers Pangolin's dashboard and API, every resource, the domain redirects, and the 401/403 Traefik writes itself. It sets `Strict-Transport-Security: max-age=31536000`, `X-Content-Type-Options: nosniff` (since 2026-11-11), replacing an app's own, and empties `Server` and `X-Powered-By`. No `includeSubDomains`, no `preload`: `nas.`, `media.` and `mediamanager.sylvain.cloud` are served by the NAS's Traefik, outside this proxy, and a preload entry cannot be taken back. Port 80 (ACME, redirects) gets no header. CSP, frame options and `Referrer-Policy` stay with each app: one global policy would break some of them (no `frameDeny`), and a global `Referrer-Policy` would replace the stricter one of `docs_site` (`same-origin`) or Nextcloud (`no-referrer`) with the browsers' default anyway. Traefik's `/ping` is served on the public `web` entrypoint (port 80); moving it to an internal entrypoint is left undone, the probes read it. Rollback: take `security-headers@file` off the entrypoint first and keep the middleware defined until the stack has restarted (a later PR removes it): Traefik reloads the dynamic file at once but its static config only at the handler, and an entrypoint naming a missing middleware breaks every HTTPS route in between, as for `crowdsec@file`. A plain revert of this change opens that window.

## TLS

- `traefik_dynamic_config.yml.j2` sets the Traefik `default` TLS option (all public names, Pocket ID included): `VersionTLS12` minimum and ECDHE + AEAD suites only (AES-GCM, ChaCha20-Poly1305), no CBC (LUCKY13); TLS 1.3 is unaffected. The file provider reloads it live, no Traefik restart.

## Wildcard certificates (ADR 0031)

- One Let's Encrypt wildcard per zone, `*.sylvain.cloud` and `*.sylvain.dev`, instead of one certificate per name, so new names stop reaching the Certificate Transparency logs. Active as soon as the three SOPS keys `pangolin_ovh_application_key`, `_application_secret` and `pangolin_ovh_consumer_key` are set (`pangolin_wildcard_cert`, defaults): Traefik gets a second resolver `letsencrypt-dns` (DNS-01 through the OVH API, `OVH_*` in the 0600 `compose.yaml`, same `acme.json`, its own ACME account), `domain1` of `config.yml` gets `cert_resolver: letsencrypt-dns` and `prefer_wildcard_cert: true` (Pangolin rewrites them into its database at every start, `copyInConfig.ts`, so `pangolin_domain.org` in `tofu/pangolin_config/domains.tf` carries the same values, and is the only owner of sylvain.dev), and the file routers of sylvain.cloud (dashboard, API, Pocket ID) share the YAML anchor `tls-base-domain`. The global `letsencrypt` resolver (HTTP-01) stays for the other names (the sylvain.dev apex service worker, other domains): HTTP-01 cannot issue a wildcard.
- The CAA `issuewild` of both zones (`tofu/dns/caa.tf`) allows Let's Encrypt by DNS-01 only, then only the ACME accounts of this Traefik and the NAS's (`accounturi`, read in `acme.json`, `docs/runbooks/dmarc.md`).
- **Traefik prefers a per-name certificate over the wildcard** (exact match first) and keeps renewing every certificate of `acme.json`: until the former per-name certificates are removed from it (Traefik stopped, `jq`), they are still served and renewed. A name that never had one (`acme-test.sylvain.cloud`) shows the wildcard.
- Staging trial by hand only, **before** `domains.tf` is applied (it drops `letsencrypt-dns`, which sylvain.dev points at afterwards: its routers would go down for the trial): `ansible-playbook pangolin.yaml --tags pangolin -e pangolin_wildcard_staging=true -e pangolin_wildcard_cert=false` renders `letsencrypt-dns-staging` (its own `acme-staging.json`) and a router `acme-staging-test` on `pangolin_wildcard_test_host` (`noop@internal`); `openssl s_client -connect acme-test.sylvain.cloud:443 -servername acme-test.sylvain.cloud </dev/null | openssl x509 -noout -issuer -ext subjectAltName` shows a `(STAGING)` issuer and `*.sylvain.cloud`. Run the playbook again without `-e` right after, then delete `acme-staging.json`: a staging wildcard left in Traefik's store makes the real one look already covered, and it is never ordered.
- One level only (`a.b.sylvain.cloud` is not covered; an apex is served by exact name). An expired wildcard takes the whole zone down at once: the Uptime Kuma HTTP monitors (`expiry_notification`) watch it. Rollback: `pangolin_wildcard_cert: false` and `prefer_wildcard_cert = false` in `domains.tf`.

## Identity provider route (Pocket ID)

- `traefik_dynamic_config.yml.j2` also carries, when `pangolin_idp_host` is set (`host_vars/pangolin`, only if the SOPS key `pocket_id_encryption_key` exists; ADR 0030), a direct router pair for `id.sylvain.cloud` (`pocket-id-router-redirect` on `web`, `pocket-id-router` on `websecure` with the sylvain.cloud TLS of the file routers, the wildcard when `pangolin_wildcard_cert`), the service `pocket-id-service` (`pangolin_idp_upstream`, the `pocket-id` container of the `pocket_id` role on the `pangolin` network) and the middlewares `pocket-id-ratelimit` (per source IP) and, while `pocket_id_setup_phase` is true, `pocket-id-allowlist` (`home_ip` only). It is a router of the file provider, **never** a Pangolin resource and never behind Badger: it serves the login of the wall, which could not protect it. Hence no FR/DE filter either (exception to ADR 0002). `security-headers@file` and `crowdsec@file` still apply from the entrypoint. Every other router and middleware of the file is untouched; with the variable empty nothing of it is rendered (the Molecule scenario `pangolin` checks both the router and the unchanged `next-router`). Rollback: empty the variable (remove the SOPS key) and `pangolin.yaml --tags pangolin`; Traefik reloads the file at once, no restart needed.

## CrowdSec

- CrowdSec on Pangolin (`docs/runbooks/crowdsec.md`): container `crowdsec` (agent + LAPI + AppSec, digest-pinned, data under `/opt/pangolin/crowdsec`, never backed up) in the pangolin compose, reading Traefik's JSON access log (`config/traefik/logs`, rotated daily by `/etc/logrotate.d/traefik-access` with SIGUSR1, excluded from borgmatic); bouncer = Traefik plugin `maxlerebourg/crowdsec-bouncer-traefik-plugin` (tracked by the same Renovate regex as badger) as `crowdsec@file` on the `websecure` entrypoint only (port 80/ACME untouched), `stream` mode, failing open (`updateMaxFailure: -1`, AppSec `*Block: false`). AppSec is detect-only: every rule loaded `outofband` (`homelab/appsec-alert-only`), so alerts, never a 403 or a ban. Client IP = the TCP peer (no `forwardedHeaders`/`forwardedHeadersTrustedIPs`); `home_ip`, Pangolin's public IP, private ranges and `pangolin_crowdsec_whitelist_extra` are both an s02 whitelist and `clientTrustedIPs` (the latter is what protects them from the community blocklist). Bouncer key: SOPS `pangolin_crowdsec_bouncer_key`, re-registered on every container start (compose `entrypoint` deletes `traefik` and the `traefik@<ip>` rows the LAPI adds): a LAPI key that differs makes AppSec answer 401 and the plugin 403 every request. Rollback: `pangolin_crowdsec_enabled: false` (`pangolin_crowdsec_appsec_enabled: false` for AppSec only) and `pangolin.yaml --tags pangolin`; while disabled, `crowdsec@file` stays defined as a no-op headers middleware, since Traefik reloads the dynamic file at once but its static config only when the stack restarts (handlers flushed at the end of the role, before borgmatic).

- CrowdSec on Pangolin also sends a weekly summary to ntfy (`crowdsec-summary.timer`, Monday 07:30, pangolin role: `files/crowdsec-summary.py`, stateless, runs `docker exec crowdsec cscli alerts list --since 168h` and `decisions list`: alerts by scenario and country, active decisions, AppSec alert-only hits; priority low, high on any AppSec hit or a dead cscli). Topic and token of the `scripts` producer (`ntfy_scripts_token`, in the 0600 `/etc/crowdsec-summary/env`, never on a command line); removed with CrowdSec or without a token. `docs/runbooks/crowdsec.md`.

## GeoLite2

- GeoLite2 (the geo filter of every public resource) is refreshed weekly on Pangolin by `geoipupdate.timer` (pangolin role: the official MaxMind image, pinned; free account, `pangolin_maxmind_*` in `secrets/ansible.sops.yaml`), which restarts the `pangolin` container only when the Country database changed and pushes to the `GeoIP Pangolin` monitor (`uptime_cron_geoip_url`). Since 2026-11-06 it fetches `GeoLite2-Country` and `GeoLite2-City` into `pangolin_geoip_dir` (`/opt/geoip`, 0755, files 0644), mounted read-only in Pangolin (`/app/geoip`, `maxmind_db_path`) and in Pocket ID (`GEOLITE_DB_PATH`, approximate places of its audit log, which it reloads by itself); the former copy in `config/` is no longer read. Same MaxMind account, no new key.

## Docker daemon restart

- Docker restarts the containers with a restart policy when the daemon opens, one by one; a start that fails there is only logged (`failed to start container`) and never retried. Traefik shares gerbil's network namespace (`network_mode: service:gerbil`), so a failed gerbil or a Traefik started too early stays `Exited` with every public site down (12/11/2026, 4 minutes after `apt install --only-upgrade docker-ce`; `docs/incidents/pangolin-traefik-reste-arrete.md`). `pangolin.service` is a oneshot with `Wants=docker.service` (not `Requires=`: a `Requires=` stopped the stack with the daemon and nothing brought it back), so it does not run `compose up` again when Docker returns.
- The drop-in `/etc/systemd/system/docker.service.d/pangolin.conf` (`docker-pangolin.conf.j2`) adds `ExecStartPost=-/usr/bin/timeout 30 /usr/bin/docker start pangolin gerbil traefik crowdsec`: once the daemon is ready (restoration finished: the API only answers after it, checked on the bench), whatever is stopped is started, in that order, a manual `docker stop` included (no opt-out: stop the stack with `systemctl stop pangolin` for maintenance); a running container is untouched, and a missing one (stack taken down by `docker compose down`) is an ignored error. Written without a handler: it applies at the next start of `docker.service` and recreates nothing. Rollback: delete the file, `systemctl daemon-reload`.

## Rebuild / restore

- Database copies: Pangolin copies its SQLite DB (~2 GiB each) to `config/db/backups/` before every migration and never purges them. They are excluded from borgmatic (the live DB is dumped), and `/etc/tmpfiles.d/pangolin-db-copies.conf` (`e` rule, run daily by `systemd-tmpfiles-clean.timer`) deletes those older than `pangolin_db_copies_retention_days` (30). Age only: the newest copy is not kept if it is old.

Server image, Hetzner backups and the rebuild order: `tofu/pangolin/README.md`.
