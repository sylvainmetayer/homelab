# Role `newt`

Moved from `AGENTS.md` (agent-facing notes, kept in English); the index there links here.

- The Pangolin `newt` container must share a Docker network with any app it fronts: it proxies to them over the `newt` bridge. Newt never mounts the Docker socket either: its sidecar `newt-socket-proxy` (`ansible/roles/newt/defaults/main.yml` lists each allowed call and why) lets through only the calls read off newt 1.19.0's `docker/docker.go` (a file 1.19.1, the image on 2026-11-03, leaves unchanged), and no inspect of other containers (their env, hence every compose's secrets). A newt bump must re-read `docker/docker.go` against that list; a missing call only empties Pangolin's container list (proxy logs a 403).
- **Second réseau `newt-public`** (`newt_public_network_enabled`, faux par défaut, vrai dans `host_vars/flip` et `host_vars/docker`) : le compose de Newt le crée à côté de `newt` et Newt rejoint les deux. Les applis publiques **sans SSO** (`sso = false` dans `tofu/pangolin_config` : Promptoramix sur flip, Bêtisier sur docker, Exemple Planning sur flip tant qu'il est en pause) y vont à la place de `newt` et ne voient plus les applis derrière le SSO (Grocy, qui fait confiance à `Remote-User`, Flip Planning, Homepage…). Elles lisent la même variable (`promptoramix_newt_network`, `betisier_newt_network`) ; la cible Pangolin reste le nom du conteneur, que Newt résout par le DNS Docker des réseaux qu'il partage avec lui. Une base ne rejoint jamais `newt` ni `newt-public`. Le réseau doit exister avant l'appli : `newt` passe avant elle dans chaque playbook (ses handlers aussi). Jamais sur le drill (`docker_drill` ne crée que `newt`, et `host_vars/docker` ne s'y applique pas). Les applis dont seul un chemin est ouvert (`local.path_bypasses`) restent sur `newt`. Activé sur docker (2026-11-11) : le premier déploiement recrée Newt (`newt` d'abord dans `docker.yml`, deux réseaux), ce qui coupe un instant toutes les applis publiques de la VM, puis Bêtisier est recréé sur `newt-public`.
- **Exemple Planning n'est pas encore sur `newt-public`** : en pause, et le rôle `flip_planning` lit le sous-réseau de `newt` une fois pour toutes ses instances (proxys de confiance) ; à traiter avant de la rétablir (réseau et sous-réseau par instance).
- `newt_subnet` (empty by default): pins the subnet of the `newt` Docker network (`ipam` in the compose). Only `host_vars/nas` carries it, empty on purpose until the ordered procedure of `roles/nas_proxy/README.md` is run: Compose recreates an existing network only if it carries the config-hash label of a recent Compose, and refuses while a container of another project (`nas-proxy`) is attached, so the procedure stops both units and removes `newt` by hand. It lets `nas_proxy` filter its routers by source (`nas_proxy_newt_subnet`).
