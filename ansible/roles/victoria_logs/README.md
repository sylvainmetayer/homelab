# Role `victoria_logs`

Moved from `AGENTS.md` (agent-facing notes, kept in English); the index there links here.

## Logs (VictoriaLogs + Vector agents)

The agent role is `log_agent`, whose README points here.

- Logs are VictoriaLogs, the light version (#79, `docs/adr/0011-journaux-victorialogs.md`, accepted 2026-11-09 after the one-week measurement; `docs/architecture.md`, « Les journaux »): role `victoria_logs` on the Docker VM (storage on an internal network only, 30 days, `-retention.maxDiskSpaceUsageBytes` 5 GiB, no backup by design) behind vmauth (`victoria-logs-auth`, the Pangolin target of `logs.sylvain.cloud` and published on `127.0.0.1`/`192.168.1.216:9428`, before ufw), which wants an account for everything but `/health`: a browser on `logs.sylvain.cloud` signs in through vmauth's SSO (v1.153+, Pocket ID client `victoria-logs`, ID token checked on issuer, audience and the `victoria-logs` group; no PKCE, vmauth sends none; cookie secret derived from `backup_passphrase`; rendered only once the Tofu outputs exist, until then the Basic `sylvain` account below serves the UI), `sylvain` (sops `victoria_logs_ui_password`) keeps only `/select/logsql/query` for scripts (`ci_key_audit`, `log_alerts`, through `127.0.0.1`, outside the SSO host), each agent (sops dict `victoria_logs_agent_passwords`, key = inventory_hostname) can only write `/insert/jsonline`, and, once the optional sops `homepage_victoria_logs_password` exists, `homepage` (Homepage's CrowdSec and Blocky cards, `ansible/roles/homepage/README.md`) can only call `/select/logsql/stats_query`, vmauth adding `extra_stream_filters` for Pangolin's `crowdsec` container stream and `blocky-check.service` on `pi` and `newt-lxc` (`victoria_logs_homepage_streams`, joined by `or`), which the client can neither override nor widen. One Vector agent per host, role `log_agent` (modes as `beszel_agent`: `dc@log_agent` on docker/pi/flip and, system scope, the NAS; `compose` on Pangolin, which also tails Traefik's access log, query strings stripped; `binary` on the newt LXC and the Proxmox host, journald only; `pve.yml` skips the role until `victoria_logs_agent_passwords.pve` exists in SOPS, then `docker.yml --tags victoria_logs` creates the vmauth account): journald plus every container through its own GET-only socket proxy (Vector needs inspect, unlike Beszel). LAN hosts post to the published port; pangolin and flip through the public resource, a PASS on `/insert/jsonline` with a per-agent Pangolin access token (`log_agent_access_tokens` output). Secrets reach Vector through its `file` secrets backend (`secrets.json`, 0600 root; `LoadCredential` in binary mode), never `${VAR}`: Vector 0.60 no longer interpolates the environment without `--dangerously-allow-env-var-interpolation`. Under `dc@`, `docker compose up` copies each container's output to its stdout (« name  | line »): `dc@` filters them out before journald (`ansible/roles/docker_service/README.md`), and the journald transform still drops any that get through (a unit not yet restarted on the new `dc@`); the docker source has them with the container name. Both transforms mask known token patterns in the message before sending, and the Traefik one in the request path (`log_agent_redactions`: Uptime Kuma `/api/push/<token>`, HealthLog's Withings `/api/withings/webhook/<secret>`, ntfy `tk_…`, Pocket ID's login codes `/lc/<code>` and `/api/one-time-access-token/<code>`), a safety net only: the rule stays « no token in a log line nor on a command line » (`_CMDLINE` is not shipped, but stays in the host's journal). Push URLs are read by curl from a `0600` config file (`-K`, or on stdin) everywhere, through the shared `uptime-push` helper (`ansible/roles/uptime_push/README.md`), borgmatic included. A leaked line ages out with the 30-day retention; deleting it sooner needs VictoriaLogs' delete API, off by default (`-delete.enable`, then `POST /delete/run_task?filter=<LogsQL>` on the storage container, which vmauth does not route).

### MCP server (natural-language queries from Open WebUI)

The official VictoriaLogs MCP server (`ghcr.io/victoriametrics/mcp-victorialogs`, v1.9.0 pinned by digest, Streamable HTTP on `:8081/mcp`) runs as the `mcp-victorialogs` container of this compose, toggled by `victoria_logs_mcp_enabled`. Owned here rather than by `openwebui` because everything it needs lives here: the vmauth account, the token, the vmauth network. It reaches VictoriaLogs only through vmauth, with a dedicated Bearer account (`victoria_logs_mcp_token`, derived from `backup_passphrase`, no SOPS key) that can only call `/select/logsql/.*` (no vmui, no insert, no `/flags`, whose tool is disabled). Two internal networks, no egress: `mcp-auth` (vmauth and the MCP) and `victoria-logs-mcp` (the MCP and Open WebUI, which declares it `external`, hence `victoria_logs` runs before `openwebui` in `docker.yml`). No `newt` network, no published port, no Pangolin resource: `/mcp` has no authentication of its own, the network is the barrier. The tool is declared in Open WebUI without access grants, so only its admins (Sylvain) see it (`ansible/roles/openwebui/README.md`). Hardened like the others (`read_only`, `cap_drop: ALL`, `no-new-privileges`, deploy uid), `mem_limit: 128m` not measured yet (recheck `memory.peak`). Stateless: no backup. Not in Renovate's automerge allowlist: it restarts the whole compose project (storage included) and holds a read token, like vmauth.
