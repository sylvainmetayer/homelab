# Role `nas_proxy`

Moved from `AGENTS.md` (agent-facing notes, kept in English); the index there links here.

Part of `nas.yml` (row in `docs/conventions/ansible.md`).

Then `nas_proxy` (`dc@nas_proxy`, container `nas-proxy`: Traefik, file provider only, no Docker socket, Let's Encrypt by DNS-01 with the OVH key `nas_ovh_application_key`/`_secret`/`nas_ovh_consumer_key`, `acme.json` `0600` root under `docker_base_path`) fronts three names; out of reach of the PikaPods Uptime Kuma, their certificates are checked on the NAS itself by the daily `nas-proxy-cert-check.timer` (`files/cert_check.py`, Python stdlib against `127.0.0.1:8443` with each name as SNI, system CA store), which pushes up, or down under `nas_proxy_cert_check_min_days`, to the `Certificats NAS` monitor (`uptime_cron_nas_cert_url`). `https://media.sylvain.cloud` (Jellyfin), `https://nas.sylvain.cloud` (UGOS's UI, `http://<NAS LAN IP>:9999` behind it) and `https://mediamanager.sylvain.cloud` (MediaManager trial, `http://mediamanager:8000` on the `mediamanager_proxy` network that `dc@mediamanager` creates, joined as external, hence `nas_proxy` after `mediamanager` in `nas.yml`), with or without `:8443`, at home and through the Pangolin client (public A records `tofu/dns/media.tf`/`nas.tf`/`mediamanager.tf` to the NAS's LAN IP, beating the `*.sylvain.cloud` wildcard, each in Blocky's `blocky_rebinding_allowed_domains`; private resources `media.sylvain.cloud` and `mediamanager.sylvain.cloud`, site `nas`, `nas-proxy` on the `newt` network, TCP 443 and 8443, and `nas`, site `proxmox-lxc`, LAN IP, TCP 22, 443, 445, 8443, 9999). Jellyfin's and MediaManager's routers have no source filter: both Pangolin resources reach the same `nas-proxy` ports, so a `jellyfin` role member can reach MediaManager's login page by asking for its name (and the other way round), like any LAN device; each app's own account is the gate. Only `ugos` is LAN-only (`ugos-lan`). `8443` is published by Docker on `nas-proxy`. The host's `443` is **not** published: it is held by a second service of the same compose, `forward` (container `nas-proxy-443`, same Traefik image, `network_mode: host`, TCP passthrough to `nas-proxy`'s unpublished `websecure-forwarded` entrypoint `172.30.96.10:8444` with PROXY protocol v2, trusted from the host's `jellyfin_media` gateway `172.30.96.1` only, so `ugos-lan` and Jellyfin still see the client IP). Port 443 is free only while UGOS's "redirect HTTP/HTTPS to the UI's HTTPS port" setting is unticked (`defaultHttpsRedirectEnable` in `/etc/nginx/config.json`, a 307 to `:9443` in `ugreen_ssl_redirect.conf`); if a UGOS update ticks it again and nginx starts first, the relay's Traefik exits on bind and Docker retries it (back-off up to 1 min) while `nas-proxy` and `:8443` keep running (nothing orders nginx before Docker: if the relay holds 443 first, nginx fails and the whole UGOS UI with it; `docker stop nas-proxy-443`, restart nginx, untick, `docker start nas-proxy-443`) — a published 443 would instead fail the container create, hence `up`, and `dc@`'s `ExecStop` would stop `nas-proxy` on every retry. The role flushes its handlers then fails (`tasks/host_https_port.yml`, `ss -p`) when anything but the relay listens on the host's 443. Port 80 stays with UGOS's nginx (DNS-01 needs none).
