# tofu/pangolin_config

Moved from `AGENTS.md` (agent-facing notes, kept in English); the index there links here.

`tofu/pangolin_config/` — Pangolin-side application config (roles, rules, private resources, per-app `website_*.tf` files declaring each public app as an entry of `local.websites`, from which `websites.tf` generates the resources, targets and Uptime Kuma checks) applied against the running Pangolin instance, separate from the VM provisioning itself. Its state is what `00-setup.yaml`/`docker.yml`/`flip.yml`/`lxc.yml`/`nas.yml`/`pangolin.yaml`/`pi.yml`/`pve.yml` read at Ansible time for healthcheck and SSH-login push URLs (and, for `flip.yml`, `lxc.yml` and `nas.yml`, the Newt credentials of the `flip`, `proxmox-lxc` and `nas` sites). It reads `tofu/pangolin`'s state (`remote_state.tf`) for flip's private IP, so `tofu/pangolin` is applied first. Every public resource is declared there — there is no hand-made public resource left (`SSH PI`, the last one, was deleted in favour of the private `pi.internal`; Proxmox and the NAS are private too since, `pve.internal` and `nas.sylvain.cloud` in `private_resources.tf` (the latter an alias that is also a public A record to the NAS's LAN IP, `tofu/dns/nas.tf`, served by the Newt LXC), like `media.sylvain.cloud` (an alias that is also a public A record to the NAS's LAN IP, `tofu/dns/media.tf`), served by the NAS's own Newt on site `nas` and opened to the `pangolin_role.jellyfin` members, and `mediamanager.sylvain.cloud` the same way (`tofu/dns/mediamanager.tf`, same `nas-proxy` destination and ports, `pangolin_role.mediamanager`; Traefik picks the app by name, so either role can reach the other app's login page: each app's own account is the gate), and the coverage precondition in `rules.tf` fails the plan on any enabled resource missing from `local.managed_resources` (derived from `local.websites`), so a resource created in the UI must be deleted or disabled there before the next apply. Optional+computed attributes of `pangolin_resource` (`mode`, `ssl`, `enabled`…) come from `local.resource_pins` (`resource_defaults.tf`); an entry may override `enabled` (false pauses the app: resource disabled, healthcheck and backup monitors paused, its targets' Pangolin probes off (`hc_enabled`), see « Pausing an app » in `docs/conventions/app-lifecycle.md`); paperless and demo_planning_kc do today. The Uptime Kuma monitors need no such local: in `breml/uptimekuma` 0.5.0 every optional+computed attribute (`upside_down`, `active`, `max_retries`…) has a static provider default and is read back on refresh, so a value changed in the UI shows in the next plan (re-check on a provider upgrade, see `uptime_globals.tf`). `resource_policy_id = 0` is one of those pins: a shared policy attached in the UI wipes the resource's rules and grants, and now shows in a plan. `headers` and `response_headers` are optional only, not computed, so they stay out of the config (`websites.tf`): the fork reads them back and absence means none, so a header set by hand in the UI shows in the next plan and the apply removes it. The two VPN exit nodes, site resources `vpn` (sites proxmox-docker, Raspberry PI, proxmox-lxc, nas) and `vpn-flip` (site flip) in `gateway` mode, are declared in `private_resources.tf`; made in the UI first, they were imported once with `tofu -chdir=tofu/pangolin_config import pangolin_site_resource.vpn 16` and `... pangolin_site_resource.vpn_flip 17` (no `import` block: this module is tested). `00-NTF-nas` (`nas_web`, the NAS on port 9999 at `nas-internal.sylvain.cloud`) came the same way: `... pangolin_site_resource.nas_web 11`. An in-place update of a `pangolin_site_resource` keeps its bindings: the fork omits `roleIds`, `userIds` and `clientIds` from the body, and Pangolin 1.20+ leaves them unchanged. A binding made in the UI is therefore left alone and invisible to the plan: declare every wanted binding.

## Provider: a build of the fork

The Pangolin provider is `1.7.0-sylvain.1`, built from `sylvainmetayer/terraform-provider-pangolin` and pinned exactly in `provider.tf`. Run `mise run provider-fork` before `tofu init` in this module (once per clone or worktree; `lint`, `tofu-test` and the CI do it): without it, `init` fails on a version the registry does not have. The zip lands in `terraform.d/plugins`, an implied mirror needing no CLI configuration, as long as no `provider_installation` block exists in `~/.tofurc`. Rerun it after a version bump. linux_amd64 only. Why: ADR 0021.

The optional+computed attributes the fork adds are declared (`AGENTS.md`'s hard rule): `resource_policy_id` on `pangolin_resource`, `site_ids`, `ssl` and `enabled` on `pangolin_site_resource`. The ones left undeclared have their reason next to the resources (`resource_defaults.tf`, `private_resources.tf`), and the plan stays blind to their live value. Some 1.6.1 workarounds stay although the fork lifts them (`udp_port_range = "*"` in `private_resources.tf`: 1.6.1 dropped an empty string, the fork sends it), each to be reconsidered on its own.

Way back, once upstream has what the config uses. First, in every checkout and worktree, `rm -rf tofu/pangolin_config/terraform.d`: a provider found in an implied mirror is hidden from the registry, so with the fork's zip still there `init` finds no release matching an upstream constraint. Then read what that release sends on a `pangolin_site_resource` update: if it still sends empty `roleIds`/`userIds`/`clientIds` (1.6.1 did), every update wipes the bindings, the CI runner's included, and the empty plan below will not show it. In that case first put `lifecycle { replace_triggered_by = [pangolin_site_resource.<x>] }` on every binding, never with `create_before_destroy` (the new binding would be refused as already present, then the old one's removal would drop it), and bring back the test `site_resource_bindings_follow_their_resource` (removed by #1127). Then put a normal constraint back in `provider.tf`, `tofu init -upgrade`, check an empty plan, and remove the script, the `provider-fork` task and its `depends`, the CI steps, the `select_tests.py` entry and its test, the Renovate rule, `terraform.d/` from `.gitignore`, this section and the three `AGENTS.md` lines about the fork (the `provider-fork` command, « Current state », and the bindings rule, restated if upstream still wipes).

## Pangolin alerts and LAN probes

`alerts.tf` declares three alert rules (site offline, resource down, probe failing) that publish to ntfy, and the `pangolin_health_check` probes the LXC's Newt runs on the LAN. It also holds `Ressource Alerts`, an email rule on every resource's health changes (`resource_toggle`, despite its name, follows healthy, unhealthy and degraded, not a resource being enabled; a 5-minute cooldown, so a site going offline does not send one email per resource, and a second outage inside it sends none), made in the UI first and imported once with `tofu -chdir=tofu/pangolin_config import pangolin_alert_rule.resource_toggle 3`. They need the `createAlertRule`, `listAlertRules`, `getAlertRule`, `updateAlertRule`, `deleteAlertRule`, `createHealthCheck`, `listHealthChecks`, `updateHealthCheck` and `deleteHealthCheck` actions on the Pangolin API key (403 on apply otherwise). Both resources exist only in the fork (ADR 0021). None replaces Uptime Kuma: the three rules go through ntfy, on the Docker VM, so the `proxmox-docker` site going offline, or Pangolin itself, sends nothing, and the 5-minute delay is per rule, so a second outage inside it is never sent (`alerts.tf`). The probe rule watches the LAN probes only, not the targets' probes.

## Public resources: country rules and path bypasses

Every public Pangolin resource only lets FR and DE through (`tofu/pangolin_config/rules.tf`; `apply_rules = true` on all of them, pinned by the `every_public_resource_applies_its_rules` test, which also pins Betisier and Promptoramix as the only resources without SSO; `php_lockdown.tf` disables the Monica path ACCEPTs until a critical PHP vulnerability is patched (its `php_lockdown_sso` list, which can force a resource behind the SSO, is empty today); FreshRSS has none, it is read in the browser only, its API off), except the rules evaluated before the country rules. Priority 1 is a DROP of any path holding a backslash (`backslash_guard`) on every resource that has a path rule, since Pangolin does not normalise `\` and Node turns it into `/`. Priorities 2-9 hold the path ACCEPTs that answer from anywhere without SSO, protected by the app's own secret: share links, calendar feeds, client APIs, MCP/OAuth, Enclosed's note reads (`website_enclosed.tf`: one-segment globs `0*`, since a bare trailing `*` also matches zero segments and `/api/notes/*` would open the creation route `/api/notes`), and Promptoramix's whole `/*` (called by the Linkx tournament's Supabase edge functions from anywhere, guarded by its HMAC signature check — the one deliberate whole-app bypass). Each app lists them next to its resource as `local.<app>_*_paths` (path => priority), aggregated in `local.path_bypasses`. Nextcloud is behind the SSO like the rest: its clients (WebDAV/OCS, the client half of login flow v2, Android's `/index.php/204` connectivity check) and its public share links go through `local.nextcloud_client_paths` / `local.nextcloud_share_paths` (`website_nextcloud.tf`), and the `nextcloud` role sets `token_auth_enforced` (app passwords only on DAV/OCS) and `trusted_proxies` (the `newt` subnet, for the real client IP) in `config/www/nextcloud/config/homelab.config.php`. Those paths were read off one version of each third-party image, noted in `tofu/pangolin_config/path_bypass_images.json` (the `path_bypasses_follow_their_image` test checks it against the compose files and that every `local.path_bypasses` resource is listed or explicitly exempted). Renovate bumps that file together with the compose (custom manager), so no hand commit is needed; the PR never automerges (last `packageRules` entry) and its `prBodyNotes` ask the reviewer to read the release notes (`releases`) and the sources listed in the entry's `reread` before merging by hand. If a route moved, fix the app's `_paths` in the same PR before merging. Every path ACCEPT goes through `local.path_bypasses`, Karakeep's public lists, TREK's OAuth surface and the planning `/mcp/*` and KC `/auth/*` rules included (`pangolin_resource_rule.path_bypass["<Resource name> <path>"]`; a rule leaving a standalone resource for it needs a `moved` block, removed once applied). Priorities 2-9 also hold the only standalone path rule, TREK's `/mcp` PASS (`trek_mcp`: skips the country rules, still requires SSO or a Pangolin access token; `local.standalone_path_rule_resources` keeps its backslash guard, and the `tied_rules_share_their_action` apply run fails if any PATH rule's resource has none), and the home-IP ACCEPTs at 9. Rules sharing a priority on one resource must share their action (`tied_rules_share_their_action` test). For a trip, add the country with an end date to `travel_countries` (`tofu/pangolin_config/variables.tf`) and apply: it gets its own priority (20), and the first apply after that date closes it again (the `travel_countries_stale` check then asks for the entry to be removed). Nothing applies `pangolin_config` on a schedule, so it stays open until someone does.
