# tofu/pangolin_config

Moved from `AGENTS.md` (agent-facing notes, kept in English); the index there links here.

`tofu/pangolin_config/` — Pangolin-side application config (roles, rules, private resources, per-app `website_*.tf` files declaring each public app as an entry of `local.websites`, from which `websites.tf` generates the resources, targets and Uptime Kuma checks) applied against the running Pangolin instance, separate from the VM provisioning itself. Its state is what `00-setup.yaml`/`docker.yml`/`flip.yml`/`lxc.yml`/`nas.yml`/`pangolin.yaml`/`pi.yml`/`pve.yml` read at Ansible time for healthcheck and SSH-login push URLs (and, for `flip.yml`, `lxc.yml` and `nas.yml`, the Newt credentials of the `flip`, `proxmox-lxc` and `nas` sites). It reads `tofu/pangolin`'s state (`remote_state.tf`) for flip's private IP, so `tofu/pangolin` is applied first. Every public resource is declared there — there is no hand-made public resource left (`SSH PI`, the last one, was deleted in favour of the private `pi.internal`; Proxmox and the NAS are private too since, `pve.internal` and `nas.sylvain.cloud` in `private_resources.tf` (the latter an alias that is also a public A record to the NAS's LAN IP, `tofu/dns/nas.tf`, served by the Newt LXC), like `media.sylvain.cloud` (an alias that is also a public A record to the NAS's LAN IP, `tofu/dns/media.tf`), served by the NAS's own Newt on site `nas` and opened to the `pangolin_role.jellyfin` members), and the coverage precondition in `rules.tf` fails the plan on any enabled resource missing from `local.managed_resources` (derived from `local.websites`), so a resource created in the UI must be deleted or disabled there before the next apply. Optional+computed attributes of `pangolin_resource` (`mode`, `ssl`, `enabled`…) come from `local.resource_pins` (`resource_defaults.tf`); an entry may override `enabled` (false pauses the app: resource disabled, healthcheck and backup monitors paused, its targets' Pangolin probes off (`hc_enabled`), see « Pausing an app » in `docs/conventions/app-lifecycle.md`); paperless and demo_planning_kc do today. The Uptime Kuma monitors need no such local: in `breml/uptimekuma` 0.4.0 every optional+computed attribute (`upside_down`, `active`, `max_retries`…) has a static provider default and is read back on refresh, so a value changed in the UI shows in the next plan (re-check on a provider upgrade, see `uptime_globals.tf`). `headers` is in `ignore_changes` on all of them, deliberately (`websites.tf`): a `for_each` cannot vary its lifecycle and the provider cannot remove a header anyway, so a header set by hand in the UI no longer shows in a plan. The two VPN exit nodes, site resources `vpn` and `vpn-flip` in `gateway` mode, cannot be declared (provider 1.6.1 only knows `host`/`cidr`/`http`): they are made in the UI and audited by `terraform_data.vpn_gateways` (`private_resources.tf`), which fails the plan if one is missing, not in `gateway` mode, or, for `vpn-flip`, not on the `flip` site. Any in-place update of a `pangolin_site_resource` wipes its bindings: provider 1.6.1 sends empty `roleIds`/`userIds`/`clientIds` and Pangolin replaces them (non-admin roles, users, OLM clients), while the state still holds them, so the access is gone until the next apply (seen on `jellyfin` in #869). Every `pangolin_site_resource_role`/`_user`/`_client` therefore carries `lifecycle { replace_triggered_by = [pangolin_site_resource.<x>] }` (the binding is removed before the update, re-added after it, in the same apply), enforced by the `site_resource_bindings_follow_their_resource` test. A failed update leaves the binding removed (re-run the apply), and a binding made in the UI is wiped too with nothing to restore or report it: declare every wanted binding. Still, always run a new plan after an apply that changed a private resource: it must be empty.

## Public resources: country rules and path bypasses

Every public Pangolin resource only lets FR and DE through (`tofu/pangolin_config/rules.tf`; `apply_rules = true` on all of them, pinned by the `every_public_resource_applies_its_rules` test, which also pins Betisier and Promptoramix as the only resources without SSO; `php_lockdown.tf` disables the Monica path ACCEPTs until a critical PHP vulnerability is patched (its `php_lockdown_sso` list, which can force a resource behind the SSO, is empty today); FreshRSS has none, it is read in the browser only, its API off), except the rules evaluated before the country rules. Priority 1 is a DROP of any path holding a backslash (`backslash_guard`) on every resource that has a path rule, since Pangolin does not normalise `\` and Node turns it into `/`. Priorities 2-9 hold the path ACCEPTs that answer from anywhere without SSO, protected by the app's own secret: share links, calendar feeds, client APIs, MCP/OAuth, Enclosed's note reads (`website_enclosed.tf`: one-segment globs `0*`, since a bare trailing `*` also matches zero segments and `/api/notes/*` would open the creation route `/api/notes`), and Promptoramix's whole `/*` (called by the Linkx tournament's Supabase edge functions from anywhere, guarded by its HMAC signature check — the one deliberate whole-app bypass). Each app lists them next to its resource as `local.<app>_*_paths` (path => priority), aggregated in `local.path_bypasses`. Nextcloud is behind the SSO like the rest: its clients (WebDAV/OCS, the client half of login flow v2, Android's `/index.php/204` connectivity check) and its public share links go through `local.nextcloud_client_paths` / `local.nextcloud_share_paths` (`website_nextcloud.tf`), and the `nextcloud` role sets `token_auth_enforced` (app passwords only on DAV/OCS) and `trusted_proxies` (the `newt` subnet, for the real client IP) in `config/www/nextcloud/config/homelab.config.php`. Those paths were read off one version of each third-party image, noted in `tofu/pangolin_config/path_bypass_images.json` (the `path_bypasses_follow_their_image` test checks it against the compose files and that every `local.path_bypasses` resource is listed or explicitly exempted). Renovate bumps that file together with the compose (custom manager), so no hand commit is needed; the PR never automerges (last `packageRules` entry) and its `prBodyNotes` ask the reviewer to read the release notes (`releases`) and the sources listed in the entry's `reread` before merging by hand. If a route moved, fix the app's `_paths` in the same PR before merging. Every path ACCEPT goes through `local.path_bypasses`, Karakeep's public lists, TREK's OAuth surface and the planning `/mcp/*` and KC `/auth/*` rules included (`pangolin_resource_rule.path_bypass["<Resource name> <path>"]`; a rule leaving a standalone resource for it needs a `moved` block, removed once applied). Priorities 2-9 also hold the only standalone path rule, TREK's `/mcp` PASS (`trek_mcp`: skips the country rules, still requires SSO or a Pangolin access token; `local.standalone_path_rule_resources` keeps its backslash guard, and the `tied_rules_share_their_action` apply run fails if any PATH rule's resource has none), and the home-IP ACCEPTs at 9. Rules sharing a priority on one resource must share their action (`tied_rules_share_their_action` test). For a trip, add the country with an end date to `travel_countries` (`tofu/pangolin_config/variables.tf`) and apply: it gets its own priority (20), and the first apply after that date closes it again (the `travel_countries_stale` check then asks for the entry to be removed). Nothing applies `pangolin_config` on a schedule, so it stays open until someone does.
