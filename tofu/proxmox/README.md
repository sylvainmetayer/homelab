# tofu/proxmox

Moved from `AGENTS.md` (agent-facing notes, kept in English); the index there links here.

`tofu/proxmox/` — Proxmox VE provider: the Docker VM (`proxmox_docker_vm.tf`, read back as inventory by `ansible/inventory/proxmox.py`) and the Newt LXC container (`proxmox_newt_lxc.tf`; static in `inventory/hosts`, configured by `ansible/lxc.yml`), and their nightly vzdump job (`backup.tf`: `proxmox_backup_job`, imported from the job created in the UI) onto the NFS storage `nas-backup` (export `/volume1/pve-backup` of `host_vars/nas`, client the Proxmox host only; the test pins that contract), never onto `local`, the host's root.

The Docker VM never gets rebooted by the provider: `reboot_after_update = false` (its default, `true`, would shut the VM down and start it again, every app with it, to apply a change that needs it). A change Proxmox cannot hotplug (a serial port, the CPU type…) is written to the VM config as **pending**, the apply ends with the warning « a reboot is required … Please reboot the VM manually », and it takes effect at the next **full stop**, done by hand on the Proxmox host: `qm shutdown 100 --timeout 300 && qm start 100` (a reboot from inside the guest keeps the same QEMU process, hence the old hardware; `qm pending 100` lists what waits). A change that cannot wait (resizing or moving a disk of the running VM) fails the apply instead. `serial_device` (`serial0`, a socket) backs the `console=ttyS0` of the Debian cloud image: without it, `serial-getty@ttyS0` failed every ~20 s. The default VGA display stays, so both the noVNC and the xterm.js consoles work (`qm terminal 100` too).
